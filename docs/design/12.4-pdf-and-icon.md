# Design note 12.4 — PDF export and an icon

Status: **approved 2026-11-17; built.** Last phase of Level 12
(`docs/design/levels-10-13-plan.md`).
The rule stays: **the app contains no financial logic.**

## The problem

- **A report cannot be saved as a PDF from the app.** The runner writes `report.html` (the
  portfolio report and the four studies). Today the owner opens it in a browser and prints it
  from there, which works but is not one click, and the result depends on the browser.
- **The app has no icon.** The window, the taskbar, the Start-menu entry and the installer
  show the generic one.

## PDF: three options, tried

The plan asks to consider Qt's own PDF writer before any new dependency. I tried it on the full
portfolio report of the examples (2026-11-17).

| Option | How | Result |
|---|---|---|
| **A. Qt's text engine** (`QTextDocument` + `QPdfWriter`, already in the app) | the report's HTML, as written | readable, with real page breaks and page numbers; but **the figures overflow the page** (it ignores `max-width`) and **wide tables break words** ("conto-principal / e", an ISIN cut in two) |
| A with print adjustments | the same, with each figure given the page's width, a smaller table font and A4 landscape | figures fit and tables keep their rows; **cells still touch** and a heading can land beside a figure: fixable, with more adjustments |
| **B. Qt WebEngine** (Chromium) | `QWebEnginePage.printToPdf` | prints like a browser. It needs **PySide6-Addons** (a 40 MB wheel for Windows) and Chromium's helper process in the Windows build: a large new dependency for one button |
| **C. The browser** | *Open report*, then the browser's *Save as PDF* | faithful, and possible today; not one click |

**Proposal: A, with a small print adapter in the app, and C stays available.**

- One click, no new dependency, offline, the same on every machine.
- The PDF says, on its first page, that it is a print of the report of that run, with the run's
  folder name and the date of the export.
- The adapter only changes how the HTML is laid out for Qt. It never changes a word or a number.
- If a report ever lays out badly in Qt, the browser route is one click away and is named in
  the guide.

### The print adapter (`qrlab_app.pdf`, Qt-free where it can be)

The report's HTML is read, adjusted as text, and laid out by `QTextDocument` on A4:

- **figures:** each `<img>` gets an explicit width equal to the page's text width, and sits in
  its own paragraph;
- **tables:** a cell padding (the `cellpadding` attribute, which Qt reads) and a font a point
  smaller than the text;
- **orientation:** landscape when the report has a table with more than 6 columns, portrait
  otherwise (the portfolio report's positions table has 11 columns);
- **the `dl` facts list** (a CSS grid, which Qt does not support) shows as label and value
  lines, as it does today in the test.

Each change is a rule on the HTML text, tested on its own. The tables' and paragraphs' text
must be the same in the PDF as in the HTML; a test checks it on every example report.

### In the app

- **An *Export PDF…* button** next to *Open report*, enabled when the result has a report.
- **It asks where to save,** with `<output folder>.pdf` as the name. The PDF is never written
  into the output folder: the runner's folder holds only what `record.json` lists.
- `Dialogs` gains `pick_save_file`, like the other dialogs (a fake in tests).
- **Export happens on the GUI thread:** it takes about a second for the largest example
  report. If a report proves slow, it moves to the queue later.

## The icon

- **An original mark,** drawn by a script (`packaging/make_icon.py`) with Pillow, which is
  already installed with Matplotlib: a rounded square with a rising line over three bars, in
  plain colours. No font, no logo of anyone else.
- **The script writes** `src/qrlab_app/resources/qrlab.png` (256 px, for the window) and
  `packaging/qrlab.ico` (16, 24, 32, 48, 64, 128 and 256 px, for Windows). Both are committed;
  a test regenerates them and compares the pixels, so they cannot drift from the script.
- **Where it shows:**
  - the window and the taskbar (`QApplication.setWindowIcon`);
  - both programs (`icon=` in `packaging/qrlab.spec`);
  - the installer and the uninstall entry (`SetupIconFile` in `packaging/installer.iss`).
- **The PNG travels with the package:** the wheel includes it, and the Windows build adds it
  as data.
- **Later,** Level 14's project files (`.qrlab`) use the same icon when the installer
  associates them.

## Edge cases

- **A result without a report** (a backtest): the button is off.
- **The report file is gone** (deleted by hand): the export says so and writes nothing.
- **Saving over an existing PDF:** the save dialog asks, as every system dialog does.
- **A very long report** (a study with many tables): Qt paginates it; no limit.
- **Fonts:** the PDF uses the system's sans-serif font and embeds it, as `QPdfWriter` does.

## Tests

- **The adapter, without Qt:** each rule on small HTML samples (figures, padding, the
  orientation threshold at 6 and 7 columns, the facts list), and unchanged text.
- **Every example report** (the portfolio report and the four studies' reports from test
  data): a PDF is written, it has at least one page, and the text of every table cell in the
  HTML is in the PDF's text layer (read back with Qt's own PDF reader where available, or by
  laying out the same document).
- **The button:** off without a report; the save dialog cancelled writes nothing; a missing
  report file is reported.
- **The icon:** the script's output equals the committed files pixel by pixel; the window
  has the icon; the spec and the installer name the `.ico`.
- **The self-test** exports one PDF per result that has a report, into a temporary folder, so
  the Windows build in CI proves the export works in the frozen program.

## Risks

- **Qt's HTML subset:** a future report layout could need one more adapter rule. The test on
  every example report catches a regression before release.
- **Pixel-exact icon test across Pillow versions:** if a Pillow update changes antialiasing,
  the test compares with a small tolerance instead, with the reason in the test.

## Out of scope

- PDF of the tables and charts of results without a report: the report is the document meant
  to be read; the tables are already files.
- Code signing (in IDEAS, the owner's decision).
- A macOS icon (`.icns`): with the macOS build of Level 14.

## Effort

6–8 h, as planned: about 4–5 h for the PDF and 2–3 h for the icon.

## Results and deviations (2026-11-17)

- **Built:** `qrlab_app.pdf` (the adapter and `export_pdf`), *Export PDF…* in the results
  panel with `Dialogs.pick_save_file`, the icon script and its two files, the icon on the
  window, the programs and the installer, and the PDF export in the self-test.
- **The adapter changed while building it,** because each version was checked on the printed
  report of the examples:
  - **adding a style sheet after the report's did nothing:** Qt kept the report's rules
    (padding in `rem`, which it ignores, and a body margin). **The adapter now removes the
    report's style sheet** and lays the PDF out with `PRINT_STYLE`, written for Qt (a named
    font family, sizes in points, numbers right-aligned, header shading), plus explicit
    `cellpadding` and `cellspacing` on tables. Still only layout: no word or number changes,
    and the test of every table cell holds.
  - **`QTextDocument.print_` always keeps 2 cm margins** (measured on the PDF: the text began
    32 mm from the edge with 12 mm page margins). The PDF writer now adds none, and the
    figure width is computed from those 2 cm: 642 px in portrait, 971 px in landscape, at 96
    px per inch, by hand in the test.
  - The `<figure>` element, which Qt does not know, becomes a paragraph, and its caption a
    line under the image.
- **Checked by eye:** the full example portfolio report, in landscape, three pages: the
  opening line, the facts, every table with its spacing and numbers on the right, and the
  figure inside the margins.
- **The icon:** a rounded blue square, three light bars and a white rising line, drawn at
  1024 px and scaled down; the ICO holds 16 to 256 px. The test compares the pixels exactly;
  no tolerance was needed.
- **Tests:**
  - 7 for the PDF: columns and orientation, the text width by hand, the adapter's rules and
    unchanged words, both example portfolio reports and a study-style report (wide table,
    notes, figure) with every cell in the printed text, and the two errors;
  - 3 for the icon: the committed files equal the drawing, the command line, the build and
    the installer naming it;
  - the export button: saved, cancelled, a folder that cannot take the file, the report gone,
    no save dialog; the window's icon; the self-test exporting a report, and failing when the
    export fails;
  - the app keeps 100 % coverage.
