# Design note — Phase 1.3 `qrlab.instruments`

Status: **approved 2026-11-10; implemented.** Deviations from the draft are listed at the end.

## Goal

Describe every instrument the platform analyses (above all UCITS ETFs) with validated master
data, and represent what an ETF holds at a known date. These are the inputs of later phases:

- weighted TER and cost checks (2.4);
- domicile, replication and distribution checks (2.4);
- look-through exposures and ETF overlap (2.5).

Missing or stale information is **reported explicitly**, never filled in.

## Scope

| Module | Contents |
|---|---|
| `instruments/identifiers.py` | `Isin` with check-digit validation; ISO 3166-1 alpha-2 country codes |
| `instruments/master.py` | `Instrument` master data, enums, completeness and staleness report |
| `instruments/holdings.py` | `HoldingsSnapshot` (fund holdings at an as-of date) and its checks |
| `instruments/io.py` | Loading master data (TOML) and holdings (CSV in a canonical format) with provenance |

**Layering.** The architecture puts `instruments` in layer 1, next to `data`. Loading files
with provenance needs `data.RawStore` and `data.Provenance`. I propose
`ALLOWED["instruments"] = {"core", "data"}` as a documented exception. `data` never imports
`instruments`, so there is no cycle. The layering test is updated in the same change.

**Out of scope.**
- Issuer-specific holdings downloads (iShares, Xtrackers, Vanguard, Amundi…). Each issuer has
  its own terms of use, to be reviewed before any adapter is written. Until then, holdings come
  from files the user saves into `data/` and maps to the canonical format.
- Exchange listings and trading currencies. They become necessary only when valuing
  transactions (2.1).

## 1. Identifiers

```python
@dataclass(frozen=True)
class Isin:
    code: str  # 12 characters: 2-letter country prefix, 9 alphanumerics, 1 check digit

def is_valid_isin(code: str) -> bool
def country(code: str) -> str  # validated ISO 3166-1 alpha-2, e.g. "IE"
```

**Validation:**
- No silent normalisation: lower-case letters, spaces or hyphens raise.
- The check digit follows ISO 6166: letters become numbers (A = 10 … Z = 35), then the Luhn
  algorithm is applied.
- The 2-letter prefix must be an ISO 3166-1 alpha-2 code, or one of the special prefixes
  `XS` (international) and `EU`.

Hand calculation for `US0378331005`:
- `U` = 30 and `S` = 28 give the digit string `3028037833100`.
- Luhn from the right, doubling every second digit starting with the rightmost, gives a sum
  of 45.
- The check digit is (10 − 45 mod 10) mod 10 = **5**. ✓

More cases:

| Code | Expected |
|---|---|
| `IE00B4L5Y983` | valid |
| `LU0274208692` | valid |
| `IE00B4L5Y984` | invalid (wrong check digit) |
| `ie00b4l5y983` | invalid (lower case) |
| `IE00B4L5Y98` | invalid (11 characters) |
| `QQ0000000000` | invalid (unknown country prefix) |

## 2. Master data

```python
class InstrumentType(Enum): ETF, ETC, STOCK, BOND, FUND, CASH
class AssetClass(Enum): EQUITY, FIXED_INCOME, MONEY_MARKET, COMMODITY, REAL_ESTATE,
                        MULTI_ASSET, CASH, OTHER
class Replication(Enum): PHYSICAL_FULL, PHYSICAL_SAMPLING, SYNTHETIC
class Distribution(Enum): ACCUMULATING, DISTRIBUTING

@dataclass(frozen=True)
class Instrument:
    isin: Isin
    name: str
    instrument_type: InstrumentType
    asset_class: AssetClass
    currency: Currency               # fund base (NAV) currency
    as_of: date                      # date the master data was last verified
    domicile: str | None             # ISO country, e.g. "IE"
    replication: Replication | None  # ETF/ETC/fund only
    distribution: Distribution | None
    ter: Decimal | None              # annual fraction: 0.0020 means 0.20 %
    benchmark: str | None
    hedged_to: Currency | None       # currency-hedged share class, else None
    inception: date | None
    source: str                      # where the master data came from (e.g. "KID 2026-03")

def master_data_issues(instruments, *, on: date, max_age_days: int) -> list[Issue]
```

**Rules:**
- Fields that can legitimately be unknown are `None`, never a default. `ter=None` means
  unknown, never 0.
- **TER is a fraction**, not a percentage. Values outside [0, 0.03] raise, because 3 % is far
  above any UCITS ETF TER and almost certainly a value entered in percent (e.g. `0.2` meaning
  0.20 %).
- Consistency checks that raise:
  - `replication` is set only for funds (ETF, ETC, FUND);
  - `hedged_to` differs from `currency`;
  - `as_of` is not before `inception`.
- `master_data_issues` returns `Issue(isin, field, kind, detail)` for each required-but-missing
  field (domicile, replication, distribution and TER for funds) and for each record whose
  `as_of` is older than `max_age_days` relative to `on`. `max_age_days` is required: what counts
  as stale is the caller's explicit choice. Nothing is raised, because these are findings to
  show in a report.

## 3. Holdings snapshots

```python
@dataclass(frozen=True)
class HoldingsSnapshot:
    fund: Isin
    as_of: date
    holdings: pd.DataFrame  # one row per holding
    provenance: Provenance
    weight_basis: str        # e.g. "market value, % of NAV" as reported by the issuer

# columns: name (str), isin (str | None), weight (float, decimal), country (ISO2 | None),
#          sector (str | None), currency (ISO 4217 | None), asset_class (AssetClass value)

def holdings_issues(snapshot, *, on: date, max_age_days: int, weight_tolerance: float) -> list[Issue]
def normalised_weights(snapshot) -> pd.Series  # explicit; never applied automatically
```

**Rules:**
- **Weights are decimals.** They may be negative (derivatives, cash borrowing) but must be
  finite.
- **Weights are not rescaled silently.** If their sum differs from 1 by more than
  `weight_tolerance`, `holdings_issues` reports it. Rescaling only happens through the explicit
  `normalised_weights`.
- Holding ISINs, when present, must be valid. A duplicated ISIN is reported, not merged.
- Countries must be valid ISO codes. Unknown values are `None` and counted in the report
  (the share of weight with unknown country, sector or currency).
- `sector` is free text as reported by the issuer (e.g. GICS sector names), together with the
  name of the taxonomy. Mapping between taxonomies is a look-through concern (2.5).
- **The snapshot must never be later than the date it is used for.** Use in analyses happens in
  2.5; here `as_of > on` is reported.

## 4. Loading

- **Master data:** a TOML file with one table per ISIN. Every key is checked: unknown keys
  raise, missing optional keys must be written explicitly as `"unknown"`. The real list of
  instruments you hold stays in `data/`; `configs/instruments/example.toml` is a synthetic
  example.
- **Holdings:** a CSV in a canonical column layout, or a user file plus an explicit column
  mapping (same principles as `data.user_csv`: formats are declared, never guessed). It is
  imported with `data.import_local_file`, so it has provenance and vintages.

## Edge cases (tested)

- ISIN: wrong length, lower case, whitespace, unknown prefix, wrong check digit.
- Master data: TER entered in percent, an empty name, a non-fund with a replication method,
  `hedged_to` equal to the base currency, a future `as_of`.
- Holdings: an empty snapshot, NaN or infinite weights, weights summing to 0.98 or 1.02 with
  different tolerances, negative weights, a duplicated ISIN, an invalid country code, `as_of`
  after `on`.

## Risks

| Risk | Mitigation |
|---|---|
| TER in percent instead of a fraction | Range check [0, 0.03]; unit stated in every docstring and in the example file |
| Stale master data or holdings used as current | `as_of` mandatory; staleness reported with a caller-chosen threshold |
| Holdings that do not sum to 100 % | Reported; rescaling only through an explicit function |
| Issuer terms of use | No issuer downloads in this phase; reviewed per issuer later |
| Personal data (the list of instruments you hold) | Real files only in `data/`; examples synthetic |

## New dependencies

None. The ISO 3166-1 country list is embedded as a constant with its source and date.

## Effort

12–18 h, as in the roadmap. Two PRs: (a) identifiers and master data; (b) holdings and loading.

## Deviations found during implementation

- **`Issue` also covers holdings.** Kinds: `MISSING`, `STALE`, `FUTURE`, `DUPLICATE`,
  `WEIGHTS`, `UNKNOWN_SHARE`. Unknown shares use absolute weights, so negative positions do not
  hide unknown exposure.
- **`HoldingsSnapshot` gained `notes`**, recording loading transformations (preamble skipped,
  percent → decimal, ignored columns and trailing lines). `sector_taxonomy` is required as soon
  as any sector is present.
- **Holdings files end at the first blank line.** Issuer disclaimers after it are ignored and
  counted in the notes.
- **Thousands separator equal to the delimiter is allowed**, also in `data.user_csv`. Issuer
  CSVs write `"1,234.50"` in quotes; an unquoted number changes the field count and is
  rejected per row. The decimal separator must still differ from the delimiter.
- **`data.user_csv.parse_number` is public** and shared by both CSV readers.
- **Country columns must already contain ISO codes.** Issuer files often use country names;
  a name-to-code table is deferred to look-through (2.5) and recorded in `docs/IDEAS.md`.
- **Examples use made-up ISINs** with valid check digits (`IE0000000012`, `LU0000000025`,
  `US0000000044`), so they cannot be mistaken for real funds.
