# Design note — Phase 1.1 `qrlab.core`

Status: **approved 2026-11-10; implemented.** Deviations from the draft are listed at the end.

## Scope

Shared primitives with no dependency on other `qrlab` subpackages (layer 0). Four modules:

| Module | Contents |
|---|---|
| `core/errors.py` | Exception hierarchy |
| `core/series.py` | Validation of time-indexed pandas objects; explicit NaN policy |
| `core/calendar.py` | Frequencies with explicit periods per year; business-day calendars |
| `core/returns.py` | Return kinds, price → returns, simple ↔ log, excess, compounding, aggregation |
| `core/money.py` | Currencies, currency-aware amounts, dated FX rates and explicit conversion |

Out of scope here (later phases): annualised statistics (1.4 `metrics`), FX rate *data* (1.2
`data`), vectorised multi-currency valuation (2.1 `portfolio`). The new files live inside `core`,
so `ALLOWED` in the layering test does not change.

## Design rules applied

- Pure functions; inputs are never mutated; outputs are new objects.
- No silent defaults for conventions: return kind, NaN policy, periods per year, FX direction and
  minimum observations per aggregation bucket are required keyword-only arguments.
- Invalid input raises a specific error; nothing is silently sorted, filled, aligned or dropped.

## 1. `errors.py`

```
QrlabError(Exception)
├── ValidationError(QrlabError, ValueError)     # malformed input
│   └── AlignmentError(ValidationError)         # indexes that must match do not
└── CurrencyError(QrlabError, ValueError)
    └── CurrencyMismatchError(CurrencyError)    # combining different currencies
```

## 2. `series.py` — validated time series

```python
class NanPolicy(Enum): RAISE, DROP, KEEP

def validate_series(obj: pd.Series, *, nan_policy: NanPolicy, name: str = "series") -> pd.Series
def validate_frame(obj: pd.DataFrame, *, nan_policy: NanPolicy, name: str = "frame") -> pd.DataFrame
def require_same_index(*objs: pd.Series | pd.DataFrame) -> None   # raises AlignmentError
```

A validated object has:
- a `DatetimeIndex`, either all tz-naive or all tz-aware;
- a **strictly increasing** index, which means sorted with no duplicates;
- `float64` values with no `±inf`;
- NaNs handled per `nan_policy`. `DROP` removes rows; for frames, a row is removed if **any**
  column is NaN, and this is documented.

**Unsorted or duplicated indexes raise.** They are not sorted silently, because a duplicated
timestamp usually signals a data error that sorting would hide. Callers sort explicitly.

Edge cases:
- An empty series is valid and returns empty.
- All-NaN data raises with `RAISE`, gives an empty result with `DROP`, and is unchanged with
  `KEEP`.
- A single observation is valid.
- Non-numeric dtype, object index, `inf` values or a non-`DatetimeIndex` raise.
- Booleans are rejected rather than cast to 0/1.

## 3. `calendar.py` — frequencies and business days

```python
class Frequency(Enum):            # value = pandas period alias
    DAILY = "B"; WEEKLY = "W-FRI"; MONTHLY = "M"; QUARTERLY = "Q"; ANNUAL = "Y"

CONVENTIONAL_PERIODS_PER_YEAR: Mapping[Frequency, int]  # B:252, W:52, M:12, Q:4, Y:1 — reference only
def infer_frequency(index: pd.DatetimeIndex) -> Frequency | None   # diagnostic, never used implicitly

class BusinessCalendar:           # frozen dataclass
    name: str
    holidays: frozenset[date]
    def is_business_day(self, d: date) -> bool
    def business_days(self, start: date, end: date) -> pd.DatetimeIndex

def target2_calendar(years: range) -> BusinessCalendar        # TARGET2 closing days
def weekday_calendar() -> BusinessCalendar                    # Mon–Fri, no holidays
```

Functions that annualise (in `metrics`, phase 1.4) take `periods_per_year` explicitly. The table
is a documented reference, not a silent default.

TARGET2 closing days are 1 Jan, Good Friday, Easter Monday, 1 May, 25 Dec and 26 Dec. Easter is
computed with the anonymous Gregorian algorithm (Meeus/Jones/Butcher).

Exchange calendars (e.g. NYSE or Xetra) are out of scope. A calendar with user-supplied holidays
covers them until a data source exists; they go to `docs/IDEAS.md`.

## 4. `returns.py` — return conventions

```python
class ReturnKind(Enum): SIMPLE, LOG

def prices_to_returns(prices, *, kind: ReturnKind) -> Series | DataFrame
def simple_to_log(r) -> ...          # log1p(r); r <= -1 raises (wealth would be <= 0)
def log_to_simple(r) -> ...          # expm1(r)
def excess_returns(r, rf, *, kind: ReturnKind) -> ...
def compound(r, *, kind: ReturnKind) -> float | Series        # total return over the sample
def wealth_index(r, *, kind: ReturnKind, initial: float) -> ...
def aggregate_returns(r, *, kind: ReturnKind, to: Frequency, min_periods: int) -> AggregatedReturns
```

Decisions:
- **Prices** must be strictly positive. The first observation is dropped and nothing is
  forward-filled. A NaN price makes the two adjacent returns NaN, and those are handled by the
  caller's NaN policy.
- **`excess_returns`**:
  - `r` and `rf` must have identical indexes, otherwise `AlignmentError` is raised. Indexes are
    never intersected silently.
  - Both inputs must be per-period rates of the same kind and frequency.
  - For simple returns the result is `r − rf`. For log returns it is `r − rf`, with `rf` also in
    log form.
- **`aggregate_returns`**:
  - It compounds within calendar buckets: the product of `(1 + r)` minus one for simple returns,
    the sum for log returns.
  - The result has two parts, `.returns` and `.counts`, the number of observations per bucket.
  - Buckets with fewer than `min_periods` observations become NaN, not dropped. This makes
    partial first and last periods visible instead of letting them look like full periods.
  - Any NaN inside a bucket makes that bucket NaN. A NaN is never treated as 0.
  - Labels are period ends (e.g. `2026-01-31`).

Hand-calculated examples (to be written as tests first):

| Input | Expected |
|---|---|
| prices 100, 110, 99 → simple | 0.10, −0.10 |
| same → log | ln 1.1 = 0.0953101798, ln 0.9 = −0.1053605157 |
| compound simple (0.10, −0.10) | 1.1 × 0.9 − 1 = −0.01 |
| compound log (same) | ln 0.99 = −0.0100503359 (equals log of the simple result) |
| round trip | `log_to_simple(simple_to_log(r)) == r` to 1e-15 |
| simple −1.0 → log | raises `ValidationError` |
| daily simple 0.01 × 3 in Jan, 0.02 × 2 in Feb → monthly | Jan 1.01³ − 1 = 0.030301; Feb 1.02² − 1 = 0.0404 |
| same with `min_periods=3` | Jan 0.030301, Feb NaN (counts 3, 2) |
| excess: r 0.05, rf 0.01 (simple) | 0.04 |

## 5. `money.py` — currency-aware amounts

```python
class Currency:                      # frozen; ISO 4217 code + minor units
    code: str                        # validated against a built-in ISO 4217 table
    minor_units: int                 # EUR 2, JPY 0, ...

@dataclass(frozen=True)
class Money:
    amount: Decimal
    currency: Currency
    # + - with the same currency only, else CurrencyMismatchError
    # * / by int or Decimal only; Money * Money is a TypeError
    # comparisons with the same currency only
    def rounded(self, rounding: str) -> Money     # to minor units; explicit, never automatic

@dataclass(frozen=True)
class FxRate:
    base: Currency; quote: Currency; rate: Decimal; as_of: date
    # meaning: 1 unit of base = `rate` units of quote (EUR/USD 1.25 → 1 EUR = 1.25 USD)
    def invert(self) -> FxRate

def convert(amount: Money, rate: FxRate, *, to: Currency) -> Money
```

Decisions:
- **`Decimal`, not `float`**, for `Money`. Cash ledgers (phase 2.1) must reconcile to the cent;
  `0.1 + 0.2` must equal `0.3`. Constructing from a `float` raises; use `str`, `int` or
  `Decimal`. Vectorised analytics (returns and risk) remain `float64`; this is the boundary.
- `convert` checks that `amount.currency` is the rate's base or quote and that `to` is the other
  side. Otherwise it raises `CurrencyMismatchError`. Rate staleness is checked against the
  valuation date in the data and portfolio layers, which know that date; the rate always carries
  its `as_of` date.
- Unknown or lower-case codes raise. There is no implicit base currency.

Hand-calculated examples:

| Operation | Expected |
|---|---|
| EUR 10.10 + EUR 0.20 | EUR 10.30 exactly |
| EUR 1 + USD 1 | `CurrencyMismatchError` |
| USD 100 → EUR at EUR/USD 1.25 | EUR 80 |
| EUR 80 → USD at the same rate | USD 100 |
| `FxRate(EUR, USD, 1.25).invert()` | USD/EUR 0.8 |
| JPY 1234.5 rounded half-even | JPY 1234 |
| `Money(0.1, EUR)` from a float | raises |

## Test plan

- Hand-calculated examples above, written **before** the implementation.
- Cross-checks: `numpy.log1p`/`expm1` round trips, and `pandas` resampling as an independent
  check of aggregation on random data.
- Property tests on seeded synthetic data:
  - `compound` equals the last value of `wealth_index` minus 1;
  - compounding log and simple returns agree after conversion;
  - aggregation is invariant to splitting a bucket.
- Edge cases for every public function: empty, all-NaN, single observation, unsorted index,
  duplicated index, `inf`, tz-mismatch.
- Inputs are not mutated: each test compares the input with a copy taken before the call.

## Risks

| Risk | Mitigation |
|---|---|
| Silent pandas behaviour (fill in `pct_change`, CoW changes in pandas 3) | Never call `pct_change` with default fill; tests run with warnings as errors on pandas 3 |
| Partial periods treated as full in aggregation | `min_periods` is required and the counts are returned |
| Wrong FX direction | Explicit base/quote convention; round-trip tests |
| Float rounding in cash | `Decimal` for `Money`; float construction refused |
| Different NumPy/SciPy versions across Python 3.11 and 3.13 | Tolerances in tests are explicit, never exact equality on floats except where analytical |

## Deviations found during implementation

- `easter_sunday(year)` is public (it was an internal detail in the draft) because it is useful
  for other calendars and is tested against published dates.
- `BusinessCalendar` stores the covered `years`; the draft only implied this. Queries outside
  the covered years raise, so missing holidays are never treated as business days.
- `Money.of(amount, currency)` is added as a convenience constructor from `str`/`int` and an
  ISO code; the dataclass itself accepts `Decimal` only.
- `infer_frequency` divides time deltas instead of raw index integers, because pandas 3 indexes
  may be in seconds, milliseconds, microseconds or nanoseconds (regression test added).

## Review decisions

- `excess_returns(..., kind=...)` keeps the `kind` parameter although the formula is the same
  for both kinds: it states that `returns` and `risk_free` must be of the same kind.
- `wealth_index` excludes the starting value; drawdown functions in phase 1.4 must prepend the
  initial wealth so that a loss in the first period counts as a drawdown.
- `compound` and `wealth_index` refuse NaN (a total over a gap is meaningless), while
  `aggregate_returns` accepts NaN and marks the affected bucket NaN. Intentional.
- TARGET2 from 2002 and the 36-currency `MINOR_UNITS` table are kept; extensions are in
  `docs/IDEAS.md`.
- Coverage of `qrlab.core` raised to 100% (lines and branches); one unreachable branch removed.
