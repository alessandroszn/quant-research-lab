# Design note — Phase 4.1 `qrlab.validation`: time-ordered validation splits

Status: **draft, awaiting approval.**

## Goal

Give every later estimation the same splits, which never leak:

- optimisation (4.2) and backtests (4.3);
- the studies (Level 5).

`validation` only produces splits. Models, signals and estimators are fitted by the caller
inside the training part of each split, never on the whole sample.

The one rule, enforced in code and tested on every split: **every training observation,
including the end of its label, is strictly before the first test observation.** That is
$\max(\text{train label end}) < \min(\text{test time})$. Random or shuffled splits are not
provided.

## Inputs

- **Time index:** a sorted, unique `DatetimeIndex`, validated as in phase 1.1. Splits are
  positions in this index, so they apply to any series or frame on the same index.
- **Label ends** (optional): a `Series` with the same index. For observation $i$ it gives the
  time $t^{end}_i \ge t_i$ when its label is known. An example is a 3-month forward return,
  known 3 months later.
  - Without label ends, each label is known at its own time, so $t^{end}_i = t_i$.
  - Label ends before their own time raise.
- **Sizes and steps** are counted in observations, all explicit, with no defaults:
  `train_size` or `min_train`, `test_size`, `step` and `embargo`.

## Splits

All splits are walk-forward: the test windows move forward in time and never overlap.

| Split | Train | Test |
|---|---|---|
| Expanding | positions $[0, s)$ with $s$ growing by `step`, starting at `min_train` | $[s + e, s + e + \text{test\_size})$ |
| Rolling | the last `train_size` positions before $s$, i.e. $[s - \text{train\_size}, s)$ | as for expanding |

where $e$ is the `embargo` (a number of observations skipped between train and test).

- **Purging:** training observations whose label end $t^{end}_i \ge$ the first test time are
  removed from the training set (López de Prado 2018, ch. 7). Without label ends nothing is
  purged.
- **Embargo:** `embargo` observations are skipped between the last training position and the
  first test position. This guards against dependence that purging alone does not remove (for
  example autocorrelated features).
- **Last split:** a split is produced only if its whole test window fits in the index. A
  shorter final test window is never produced silently; the number of unused trailing
  observations is reported.
- **Output:** a tuple of `Split`, each with:
  - `train` and `test` as position arrays;
  - `train_start`, `train_end`, `test_start` and `test_end` dates;
  - `purged`, the number of observations removed by purging.

  Each `Split` checks the rule on construction. The result also records the parameters and the
  unused trailing observations.
- **Helper:** `take(data, positions)` selects rows by position after checking that `data` has
  exactly the index the splits were built on. Nothing is aligned silently.

Combinatorial purged cross-validation trains on data after the test window, which breaks the
rule above, so it is not provided. It is listed in `docs/IDEAS.md` with that reason.

## Layering

`validation` stays at layer 3 and may import only `core`, as already set in `ALLOWED`. No
change.

## Hand-calculated tests

| Case | Expected |
|---|---|
| 10 dates, expanding, `min_train` 4, `test_size` 2, `step` 2, `embargo` 0 | train [0–3], test [4–5]; train [0–5], test [6–7]; train [0–7], test [8–9]; unused 0 |
| Same with `embargo` 1 | train [0–3], test [5–6]; train [0–5], test [7–8]; unused 1 (position 9) |
| 10 dates, rolling, `train_size` 3, `test_size` 2, `step` 3 | train [0–2], test [3–4]; train [3–5], test [6–7]; unused 2 (positions 8, 9) |
| 12 monthly dates, label ends 3 months later, expanding `min_train` 6, `test_size` 3, `step` 3 | split 1: test starts at position 6, so train positions 3, 4, 5 (label ends at 6, 7, 8) are purged: train [0–2], purged 3 |
| Label end before its own time | raises |
| A model fitted on `train` | never sees an index in `test`; a property test over 500 seeded random configurations checks the rule on every split |
| `take` with a different index | raises |

## Edge cases

- **Too little data:** fewer observations than `min_train` (or `train_size`) plus `embargo`
  plus `test_size` gives no split and raises, with the numbers.
- **Inputs:** sizes that are zero, negative or not integers (raise); an unsorted or duplicated
  index (raises, phase 1.1).
- **Purging:** a training set emptied entirely by purging (that split raises, saying which one).

## Risks

- **Silent leakage through features.** Splits cannot see how features were built. A rolling
  feature computed on the whole sample before splitting still leaks. The docs and the backtest
  (4.3) require features to be computed inside the training window, and 4.3 adds a leak test.
- **Too many splits on short samples.** Each split reports its sizes, and the studies report
  the number of splits.
