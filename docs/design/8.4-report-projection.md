# Design note — Phase 8.4: projection (and a savings plan) in the `portfolio_report` kind

Status: **approved 2026-11-14.** Deviations, if any, are listed at the end. Fourth phase
of Level 8 (`docs/design/level-8-plan.md`).

## The problem

The portfolio report has a projection section, built from `ProjectionResult`, with:

- the assumptions;
- the terminal percentiles;
- the probabilities with their Monte Carlo errors;
- the sensitivity table and the "not a forecast" note.

The `portfolio_report` kind always passes `projection=None`. The `projection` kind can
project a savings plan (a *PAC*), but only from an initial amount and weights typed by hand,
which are not the portfolio the report values.

## Design

Everything below is optional. Without `[parameters.projection]` the kind runs as today, byte
for byte.

### Starting point: today's portfolio

- **Initial wealth:** the portfolio's value in the base currency on the last valuation date.
- **Initial weights:** today's weights of the positions and of cash, summing to 1.
- **Start date:** the last valuation date.
- **Currency:** the base currency.

None of these is typed again.

### Assumptions: stated, never estimated from the history

Projecting the past mean forward is the overfitting this project guards against. Every return
assumption is written in the config, as in the `projection` kind:

```toml
[parameters.projection]
seed = 20261114              # random numbers are reproducible; see "Deviations to expect"
engine = { name = "student_t", dof = 5 }   # or { name = "normal" }
paths = 5000
periods = 240                # months
periods_per_year = 12
goal_real = 100000           # in today's money
percentiles = [5, 25, 50, 75, 95]
early_periods = 60
rebalance_every = 12         # periods; 0 = never
flow_timing = "start"
annual_cost = "ter"          # the weighted TER from the instruments file, or a number
inflation = 0.02
capital_gains_tax = 0.26
wealth_tax = 0.002           # e.g. the Italian stamp duty on securities accounts
flows = [{ kind = "contribution", amount = 200, first = 0, last = 239, indexed = true }]

[parameters.projection.assets.IE0000000012]   # one table per held position
mean = 0.004                 # per-period log return
volatility = 0.045           # per period

[parameters.projection.cash]                  # only when the portfolio holds cash
mean = 0.0015
volatility = 0.0

[parameters.projection.correlations]          # every pair of assets with volatility > 0
"IE0000000012 IE0000000020" = 0.85
```

- **One table per held position,** keyed by ISIN. The set must be exactly the positions held:
  a missing or extra one raises.
- **Cash** is one asset, with its own stated return. Foreign cash is part of it; its currency
  risk is left out and noted, because the projection engine has no currency model.
- **Correlations** are declared for every pair of assets with a positive volatility. A missing
  pair raises; nothing defaults to 0 or 1. A single position needs none.
- **`annual_cost = "ter"`** uses the TERs of the instruments file, weighted by today's
  weights. A position with an unknown TER then raises. A number states the cost directly.
- **Sensitivity is always computed.** In the report it cannot be switched off: projections
  always come with their sensitivity (`CLAUDE.md`).

### Outputs

- **The report's projection section.**
- **The tables and the figure of the `projection` kind:** `fan_real.csv`, `terminal.csv`,
  `sensitivity.csv`, and the fan chart with its "not a forecast" footer.
- **Scalars:** `projection_p_goal` and `projection_median_real`.
- **The notice of 7.2:** "Scenarios from the stated assumptions, not a forecast…". It is
  joined to the 8.3 price-only sentence when both apply.

## Tests (hand-calculated first)

- **Deterministic case.** With zero volatility, every path is the same:
  - today's value is 10,000 EUR, all in one fund;
  - the mean is ln(1.005) per month;
  - a contribution of 100 at the start of each month, for 12 months;
  - no cost, tax or inflation.

  By hand,
  W₁₂ = 10,000 × 1.005¹² + 100 × Σₖ₌₁¹² 1.005ᵏ = 10,616.78 + 1,239.72 = **11,856.50 EUR**.
  Every percentile of `terminal.csv` must equal it, to the cent.
- **Log-normal median.** One fund, no flows and no costs, with the normal engine: the median
  terminal value is W₀ × exp(n μ). The tolerance is stated from the Monte Carlo standard error,
  with a fixed seed.
- **Weighted TER.** Two funds at 60 % and 40 %, with TERs of 0.20 % and 0.10 %, give an
  annual cost of 0.16 %, shown in the assumptions table.
- **Starting point.** The initial wealth equals the report's end value, and the initial
  weights equal the check context's.
- **Errors:**
  - an assets table missing a held position, or naming one not held;
  - a missing correlation pair;
  - `annual_cost = "ter"` with an unknown TER;
  - a cash table missing while the portfolio holds cash.
- **Reproducibility:** the same seed gives byte-identical outputs.
- **Byte identity:** configs without `[parameters.projection]` are unchanged against `main`.
  Studies 1 and 3 are re-run.

## Deviations to expect

- **The seed is `[parameters.projection] seed`,** not `[experiment] seed`. The runner's seed
  rule is per kind: `portfolio_report` uses no random numbers unless a projection is asked for,
  so a top-level seed would be refused for every other report. The seed is in the config text,
  which the record stores.

## Out of scope (IDEAS)

- **A currency model in projections** (foreign assets and cash with FX risk).
- **The Italian tax rules of 8.6,** such as the losses balance. The projection uses a flat
  capital-gains rate and a wealth tax, as today.
- **Withdrawal plans:** they are supported by the flows (`kind = "withdrawal"`), but they are
  not given a dedicated example.

## Risks

- **Assumptions dressed as results.** The report shows every assumption next to the
  distribution, the sensitivity is mandatory, and the notice says "not a forecast".
- **Long configs.** One small table per fund, which is the price of not estimating returns.

## Effort

About 5–8 h.
