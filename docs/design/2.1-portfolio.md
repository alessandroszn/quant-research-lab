# Design note — Phase 2.1 `qrlab.portfolio`: accounting & performance

Status: **approved 2026-11-10.** At the user's request, implementation started before the
Level 1 review ended; fixes from that review will be carried forward.

## Goal

From a list of transactions, derive positions and cash per currency, value the portfolio in the
base currency with dated prices and FX rates, and measure performance correctly:

- **time-weighted return (TWR)** measures the investments;
- **money-weighted return (MWR, XIRR)** measures the investor's experience.

The two are labelled and never mixed. A hand-reconciled toy portfolio is the reference test.

Phase 2.1 also takes over **broker transaction import**, moved here from 1.2.

## Layering

`portfolio` is layer 4. It may import `core`, `data` and `instruments` (all lower layers).
`ALLOWED["portfolio"] = {"core", "data", "instruments", "metrics"}` is added in the same change;
`metrics` is needed for applying performance metrics to the TWR series.

## Modules

| Module | Contents |
|---|---|
| `portfolio/transactions.py` | `Transaction`, `TransactionKind`, validation |
| `portfolio/ledger.py` | Replay of transactions into positions, cash per currency and cost basis (`Ledger`) |
| `portfolio/valuation.py` | Daily valuation in the base currency with explicit price and FX staleness limits |
| `portfolio/performance.py` | External flows, TWR series, XIRR, P&L decomposition, contribution, currency effect |
| `portfolio/broker_import.py` | Broker CSV to transactions through an explicit TOML mapping |

## 1. Transactions

```python
class TransactionKind(Enum):
    DEPOSIT = "deposit"  # external cash flow
    WITHDRAWAL = "withdrawal"  # external cash flow
    BUY = "buy"  # trade (quantity > 0)
    SELL = "sell"  # trade (quantity > 0)
    DIVIDEND = "dividend"  # income (internal)
    INTEREST = "interest"  # income (internal)
    FEE = "fee"  # cost not attached to a trade (internal)
    TAX = "tax"  # cost not attached to a trade (internal)
    FX_CONVERSION = "fx_conversion"  # cash in one currency to cash in another
    TRANSFER_IN = "transfer_in"  # securities moved in kind (external, at market value)
    TRANSFER_OUT = "transfer_out"  # securities moved out in kind (external, at market value)
    SPLIT = "split"  # quantity ratio, no cash


@dataclass(frozen=True)
class Transaction:
    id: str  # unique, stable (e.g. broker reference)
    trade_date: date
    kind: TransactionKind
    account: str
    isin: Isin | None  # required for BUY, SELL, DIVIDEND, TRANSFER_*, SPLIT
    quantity: Decimal | None  # > 0 for trades and transfers; ratio for SPLIT
    price: Money | None  # per unit, instrument currency (trades)
    amount: Money | None  # cash amount (deposits, income, fees, taxes, FX legs)
    fees: Money  # attached to the transaction; zero if none (explicit)
    taxes: Money  # withheld taxes (e.g. on dividends); zero if none
    fx_counter: Money | None  # FX_CONVERSION: the amount received
    note: str
```

**Rules:**
- Every monetary value is `Money` with a currency, and quantities are `Decimal`.
- Consistency per kind is enforced at construction. For example a `BUY` needs an ISIN, a
  quantity, a price and fees; a `DEPOSIT` must not have an ISIN.
- The order of transactions on the same date is by `id` order as given, and recorded. It
  matters (e.g. a deposit before a buy).

## 2. Ledger (positions, cash, cost basis)

- The ledger replays transactions in date order and keeps:
  - positions per (account, ISIN);
  - cash per (account, currency);
  - cost basis per position.
- **No short positions and no negative cash** by default. Selling more than is held raises.
  Negative cash raises unless the mapping or account declares `allow_negative_cash=True`
  (margin), which is explicit.
- **Cost basis: weighted average cost, including buy fees.** This is the Italian
  "costo medio ponderato" used in the *regime amministrato*. It is kept in the instrument
  currency and in the base currency, at the FX rate of each purchase date. Realised P&L on a
  sale = proceeds − sale fees − quantity × average cost. FIFO is a possible later option and is
  recorded in `IDEAS.md`.
- `SPLIT` multiplies the quantity and divides the average cost; the total cost is unchanged.
- **Reconciliation check:** after replay, a ledger can be compared with a broker position
  statement; differences are reported as `Issue`s, never adjusted.

## 3. Valuation

```python
def valuation(ledger, prices: PriceData, fx: Dataset, *, base: Currency,
              dates: pd.DatetimeIndex, max_price_age_days: int, max_fx_age_days: int) -> Valuation
```

- On each date: Σ (quantity × price × FX to base) + Σ (cash × FX to base).
- **Prices and FX rates may be carried forward only up to the explicit age limits.** Beyond a
  limit the valuation raises or marks the date as unvalued; it never silently uses old data.
  Every carried-forward value is listed in the result.
- The FX direction comes from the ECB dataset (rates per 1 EUR). Cross rates for a non-EUR base
  are computed explicitly and recorded.
- **Price type matters:** valuation needs *price* (or NAV), not total-return indices.
  `PriceType.TOTAL_RETURN` inputs are rejected for valuation, because dividends are booked as
  cash, and using them would count dividends twice.

## 4. Performance

**Flow classification (explicit and tested):**

| Kind | Treated as |
|---|---|
| DEPOSIT, WITHDRAWAL | External flow |
| TRANSFER_IN, TRANSFER_OUT | External flow at market value on the transfer date |
| BUY, SELL, FX_CONVERSION, SPLIT | Internal (value moves between positions and cash) |
| DIVIDEND, INTEREST, FEE, TAX | Internal (part of the return) |

**TWR.** Daily chain-linking:
- `flow_timing` is required: `START_OF_DAY` gives $r_t = V_t / (V_{t-1} + F_t) - 1$;
  `END_OF_DAY` gives $r_t = (V_t - F_t)/V_{t-1} - 1$.
- The result is a daily return series ready for `qrlab.metrics`, labelled "TWR".
- Days with zero capital before the first deposit are excluded, and the reason is recorded.

**MWR (XIRR):**
- Investor-perspective flows: deposits negative, withdrawals positive, and the terminal value
  positive at the end date. ACT/365 day count.
- Solved with Brent's method on a bracket. The number of sign changes in the flows is checked
  first: no root raises, and several possible roots are reported.
- Labelled "MWR"; never compared with TWR in the same column.

**P&L decomposition (money, exact):** over a period,
end value − start value − net external flows = realised + unrealised + income − costs +
currency effect. The parts must add up to the cent. This is the reconciliation test.

**Contribution by position (per period):**
- $c_{i,t} = w_{i,t-1}\, r_{i,t}$, where cash is a position. Contributions sum to the period
  TWR return, within rounding when there are intraday flows.
- Multi-period linking (Carino or GRAP) is deferred to attribution (4.4) and stated in the
  docstring.

**Currency effect (convention stated):**
- $(1 + r_{base}) = (1 + r_{local})(1 + r_{fx})$.
- The FX effect uses the local-first convention: $(1 + r_{local})\, r_{fx}$.

## 5. Broker import

- A TOML mapping from a broker export to `Transaction`: columns, date format, separators,
  encoding, and an **explicit table from the broker's wording to `TransactionKind`**. An unknown
  wording raises.
- The example mapping is synthetic. Real exports stay in `data/`, and so do their mappings if
  they reveal personal details.
- The import goes through `data.import_local_file`, so provenance and vintages apply.
- Duplicate transaction ids raise. Re-importing the same file is idempotent, by hash.

## Hand-reconciled toy portfolio (reference test)

Base currency EUR, one ETF "X" quoted in EUR, flows at start of day:

| Date | Event | Cash | Units | Price | Value V |
|---|---|---|---|---|---|
| D0 2026-01-02 | Deposit 10,000; buy 100 X @ 50, fee 10 | 4,990 | 100 | 50 | 9,990 |
| D1 2026-01-30 | Deposit 5,000 | 9,990 | 100 | 55 | 15,490 |
| D2 2026-02-27 | Dividend 100 | 10,090 | 100 | 52 | 15,290 |
| D3 2026-03-31 | Sell 50 @ 54, fee 10 | 12,780 | 50 | 54 | 15,480 |

- **Average cost** (fees included) = (5,000 + 10)/100 = 50.10.
- **Realised gain** on the sale = 2,700 − 10 − 50 × 50.10 = **185**.
- **Unrealised gain** at D3 = 50 × (54 − 50.10) = **195**.
- **P&L** = 15,480 − 15,000 deposited = **480** = 185 + 195 + 100 (dividend). ✓
- **Period returns:**
  - D0: −0.001;
  - D1: 15,490/14,990 − 1 = 0.0333556;
  - D2: −0.0129116;
  - D3: 0.0124264.
- **TWR** = 11,863/374,750 = **3.16558 %**.
- **XIRR** of (−10,000 on 2026-01-02, −5,000 on 2026-01-30, +15,480 on 2026-03-31), ACT/365
  = **15.7293 %** a year. The MWR is high because the money was invested for less than three
  months; this shows why the two measures are never mixed.

Both values were recomputed independently of the library: TWR with exact `fractions`, XIRR with
a plain bisection solver. The tests repeat both computations.

- **Closed-form XIRR check:** −10,000 then +11,000 exactly 365 days later gives 10 %.
- **Currency example:** a USD asset rises 10 % in USD while EUR/USD moves from 1.25 to 1.20.
  - $r_{fx}$ = 1.25/1.20 − 1 = 4.1667 %;
  - $r_{base}$ = 1.10 × 1.041667 − 1 = 14.5833 %;
  - FX effect (local-first) = 1.10 × 0.041667 = 4.5833 %.

## Edge cases (tested)

- **Transactions and ledger:**
  - a sale of more than is held;
  - negative cash;
  - same-day ordering;
  - a split;
  - a dividend on a position not held (raises);
  - a fee in a currency with no cash.
- **Valuation and returns:**
  - a missing price beyond the staleness limit;
  - a missing FX rate;
  - a total-return price series passed for valuation;
  - zero starting capital;
  - a withdrawal of everything (final value 0).
- **XIRR:** all flows of the same sign (raises); several sign changes (reported).

## Risks

| Risk | Mitigation |
|---|---|
| TWR and MWR confused | Different types and labels; never in the same table column |
| Dividends counted twice | Valuation rejects total-return prices; dividends are cash |
| Stale prices or FX | Carry-forward only within explicit limits; every carried value listed |
| Currency mixing | `Money` everywhere; base conversion only through dated rates |
| Silent ledger fixes | Raise on impossible states; reconciliation differences are reported |
| Personal data | Real transactions only in `data/`; synthetic fixtures and examples |
| Tax rules | Out of scope here (configurable tax model in 3.3); average cost prepared for it |

## Deviations found during implementation

- **FX conversion spread.** An FX conversion executed at a rate different from the reference
  rate of the converter books the difference as a cost (`Cost` of kind `FX_CONVERSION`).
  Without it the P&L would not reconcile.
- **XIRR roots.** A simple bracket misses both roots when flows change sign twice (e.g.
  −100, +230, −132 has roots 10 % and 20 %). The solver scans a dense grid from −99.9999 % to
  1e8 %, solves every bracket, returns all `candidates`, and uses the one closest to zero as
  `rate`.
- **Contribution by position** is in money (realised + unrealised change + dividends), exact
  and additive. Percentage contributions linked over several periods are deferred to
  attribution (4.4). The remainder of the P&L (interest, standalone costs, cash FX effect)
  belongs to no position.
- **Cash FX effect** is computed independently from the cash movements recorded by the
  ledger, so the `residual` is a real check: zero in the hand-reconciled single- and
  multi-currency examples.
- **Valuation output** is exact `Decimal` per date (`totals`, `positions`, `cash`), with a float
  `series()` for analytics. A missing or too-old price raises rather than marking the date
  unvalued.
- **Newest-first broker exports** are reversed as a whole after checking the dates are
  non-increasing. This restores chronological order also within a day; a stable sort by date
  would have put a purchase before the deposit that funds it.
- **Charges on trades** (fees and taxes) can be in any currency. They enter the base-currency
  cost basis at the conversion rate of the trade date. The local-currency cost includes only
  charges in the instrument's currency.
- **Transfers in** take their cost basis at market value on the transfer date. Carrying an
  original cost from another broker is recorded in `docs/IDEAS.md`.
- `data.user_csv.parse_decimal` was added so that money and quantities are parsed exactly.
- **Verification:** `examples/portfolio_toy.py` imports the toy portfolio from a synthetic
  Italian-format export and reproduces TWR 3.1656 %, XIRR 15.7293 % and P&L 480 = 185 + 195
  + 100 with zero residual. An integration test checks these numbers.
