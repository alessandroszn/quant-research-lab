# Design note 11.5 — small open items

Status: **approved 2026-11-17.** Fifth and last phase of Level 11
(`docs/design/levels-10-13-plan.md`).

Three items, each a library feature that configs could not reach, or a list the owner had to
type by hand.

## 1. Loss rules in the configs

**Today:**

- `qrlab.simulation.LossRules` (8.6b) carries Italian losses in projections and backtests:
  - fund gains are capital income, taxed in full;
  - other gains are netted with the losses of the same sale, then with a balance by year,
    for `carry_years`.
- It is an optional field of `TaxModel`. The `backtest`, `projection` and `portfolio_report`
  configs cannot set it: the methodology page says so, and it is in IDEAS.

**The change: an optional `losses` table** next to each kind's capital-gains rate.

| Kind | Where | Keys |
|---|---|---|
| `backtest` | `[parameters.losses]` | `carry_years`, `fund_assets` (a list of the returns file's asset names) |
| `projection` | `[parameters.plan.losses]` | `carry_years`, `fund_assets` (a list of the asset names) |
| `portfolio_report` | `[parameters.projection.losses]` | `carry_years` only |

- **In the report the fund assets come from the instruments file:** the held ETFs and funds
  (types `etf` and `fund`). That is the rule 8.6 applies to sales; ETCs are not funds.
  - Giving `fund_assets` there is refused: the master data already says it.
  - The report's projection section names them.
- **`carry_years`** is an int ≥ 0 (4 for Italy).
- **`fund_assets`:** every name must be one of the kind's assets. An unknown name raises
  (`fund_mask` already does).
- **Without `losses`,** every output is as today.

## 2. Income tax in the standalone `projection` kind

**Today:**

- The report's projection takes `income_tax_rate` and `taxable_yield` (9.2): a yearly tax of
  their product on value.
- The `projection` kind does not, though both use the same `TaxModel`.

**The change:**

- **Two keys** in `[parameters.plan]`: the same `income_tax_rate` and `taxable_yield`.
- **Both or neither,** with the same message as in the report.
- **Without them** the projection is unchanged.

## 3. Italian country names for issuer holdings files

**Today:**

- **English:** `country_format = "name"` converts English country names with an ISO-based
  table (`qrlab.instruments.countries`).
- **Italian:** the Italian iShares files write Italian names. Their mapping must list every
  country of every fund in `country_values`, and a name not listed raises. The committed
  mapping lists 28 names for one fund, and each new fund adds more.

**The source: Unicode CLDR 49** (the npm package `cldr-localenames-full`, version 49.0.0,
22 October 2026, file `main/it/territories.json`).

- **What it gives:** the Italian name of every territory, with short forms where CLDR has
  them, for example "RAS di Hong Kong" with the short form "Hong Kong".
- **The terms,** checked on 17 November 2026: the Unicode License v3.
  - It allows use, copy and distribution of the data, with its copyright and permission
    notice in every copy.
  - So the generated table carries the notice, and the license text ships in the package
    next to it.
  - The decision is recorded in *Data sources*.
- **Other candidates:**
  - **ISO 3166** publishes no Italian names.
  - **The ISTAT list** of foreign territories (CC BY 4.0) is official, but its names are
    longer than the issuers' ("Stati Uniti d'America"). It would need more aliases.

**The change:**

- **A new value `country_format = "name_it"`** in the holdings mapping. It converts with an
  Italian table:
  - `COUNTRY_NAMES_IT`: CLDR's name and short form for every code of
    `qrlab.instruments.COUNTRIES`;
  - `COUNTRY_ALIASES_IT`: a few spellings issuers use, each checked to point to one code, for
    example "Repubblica Ceca" for CZ.
- **The table is generated once** by a script (`scripts/country_names_it.py`) and
  committed. The CLDR file is downloaded once, not at run time, and is not a dependency.
- **Matching** works as for English names: exact after ignoring case, accents and repeated
  spaces. Nothing is fuzzy. An unknown name raises and points to `country_values`, which still
  wins over the table.
- **The languages are kept apart.** English and Italian names never mix: the format says which
  table applies. A name meaning one code in Italian and another in English cannot be read
  wrongly.
- **`ishares_holdings_it.toml`** switches to `name_it`. It keeps in `country_values` only the
  lines that are not countries, such as "Unione Europea" = "unknown". Every name of its fund
  must convert to the same code as before; a test checks this.

## Edge cases (each raises, naming the key or the line)

- **`losses`:**
  - `carry_years` not an int ≥ 0;
  - `fund_assets` not a list of strings, or an unknown asset name;
  - `fund_assets` given in the report.
  - (Every kind already requires its capital-gains rate. With a zero rate `losses` changes
    nothing, and that is allowed.)
- **Income tax in `projection`:** one of `income_tax_rate` and `taxable_yield` without the
  other; a rate outside [0, 1].
- **Country names:**
  - an Italian name not in the table and not in `country_values`;
  - **the generator** fails if a code of `COUNTRIES` has no CLDR name, or if two names point
    to different codes.

## Tests, hand-calculated first

1. **Losses in the `backtest` kind.** A two-asset case from the 8.6b note, reused:
   - **the setup:** asset A, not a fund, realises a loss of 100 in year 1 and a gain of 300 in
     year 2, at 26 %;
   - **with `losses`:** tax 0 in year 1 and 0.26 × (300 − 100) = 52 in year 2;
   - **without:** 0.26 × 300 = 78.
   - **Cross-check:** the kind's result equals the engine called with
     `TaxModel(..., losses=LossRules(4, …))`.
2. **Losses in the `projection` kind and the report:** the result equals the library call
   with the same seed. In the report, the fund assets come from the instrument types (an ETF
   and a stock).
3. **Income tax in `projection`:** zero volatility and zero mean, one year, €10,000, rate 26 %
   and yield 2 %. The terminal wealth is $10{,}000 \times (1 - 0.0052) = 9{,}948$.
4. **Italian names:**
   - "Stati Uniti" is US, "Corea del Sud" is KR, "Hong Kong" (short form) is HK, "Paesi
     Bassi" is NL; case and accents are ignored;
   - an unknown name raises;
   - `country_values` still wins over the table;
   - every name of the committed iShares mapping converts to the same code as its old list;
   - the committed table equals the generator's output (the script is re-run in the test on
     the stored CLDR extract).
5. **Each error above.**
6. **Without the new keys,** byte identity against `main` on the example configs.

## Risks

- **CLDR names change between releases.** The table is frozen at version 49 and the module
  names it. A later update is a reviewed diff, never a silent change at run time.
- **An issuer's spelling differs from CLDR.** It raises with the line, as today, and the
  owner adds it to `country_values`, or it joins the aliases after review.

## Out of scope

- Names in other languages: they follow the same pattern when a file needs them.
- Estimated loss rules for countries other than Italy: `LossRules` is Italian in shape; the
  custom tax model of 9.3 has its own netting.

## Effort

4–6 h, as planned.

## Results and deviations (2026-11-17)

- **Built as designed:**
  - the `losses` tables in the three kinds, with one parser (`loss_rules` in
    `qrlab.experiments.kinds._params`);
  - the income-tax keys in `projection`;
  - `country_format = "name_it"`, `country_code_it`, `COUNTRY_NAMES_IT` (CLDR 49.0.0, every
    code, with CLDR's `-alt-short` and `-alt-variant` forms) and `COUNTRY_ALIASES_IT`;
  - the generator script and the stored CLDR file and license under `tests/data/cldr/`;
  - the license shipped as `src/qrlab/instruments/CLDR-LICENSE.txt`.
- **The CLDR license file** of the npm package has two parts. The first restricts the
  *specification* (LDML); the data files are under the Unicode License v3, the second part.
  The whole file ships with the table.
- **Typographic apostrophes:** CLDR writes "Costa d’Avorio" with U+2019, issuers usually with
  a plain apostrophe. `normalise_name` now treats both as the same, for English names too (a
  small change in `qrlab.instruments.countries`, in the CHANGELOG). The generated module keeps
  CLDR's characters, so the ruff rule on ambiguous characters is off for that file only.
- **Aliases:** three, all long official forms: "Stati Uniti d'America", "Regno Unito di Gran
  Bretagna e Irlanda del Nord" and "Corea, Repubblica di". "Repubblica Ceca" turned out to be
  a CLDR variant already.
- **The backtest test** rebalances monthly. With the example's yearly rebalancing no loss is
  realised, so the rules would change nothing to check.
- **The report's projection section** shows a "Losses" row (carry years and the funds by
  name) only when `losses` is set, so other reports are unchanged.
- **Tests:**
  - 10 tests for the `projection` and `backtest` keys: the €9,948 hand case, equality with
    the library, and every error;
  - 1 report test: the funds come from the instrument types, the report names them, and
    `fund_assets` is refused;
  - 18 tests of the Italian names: the names and forms, the languages kept apart, every code
    covered and no clash, the committed table equal to the generator's output, the generator's
    refusals and its output file, the iShares names unchanged, and the license shipped.
- **The gate:** 2664 tests on Python 3.13 and 3.11, with 100 % coverage; the docs and their
  doctests build.
- **Byte identity against `main`:** every output of the 8 example configs is equal.
- **Level 11 is complete:** M11 is marked done in the roadmap.
