# Design note 11.2 — a benchmark in the portfolio report

Status: **approved 2026-11-16.** Second phase of Level 11 (`docs/design/levels-10-13-plan.md`).

## The problem

The portfolio report gives the portfolio's own returns, risk and Sharpe ratio (8.5), but
nothing to compare them with. Three things are missing:

- **Whether the portfolio did better or worse than a reasonable alternative.**
- **How far it strays from it** (tracking error).
- **How much of its moves are the market's** (beta).

What the library already has:

- `qrlab.metrics.relative` has `tracking_error`, `information_ratio` and `capm_regression`,
  the last with alpha, beta, their standard errors, $R^2$ and $n$.
- The `risk.beta` health check (2.4) reads `CheckContext.benchmark_returns`. The kind always
  passes `None`, so with the example checks file the check is always "not applicable".
- 8.5 moved "beta on excess returns" to this phase, because it needs a benchmark.

## The change

### 1. Inputs, all optional

- **`benchmark` and `benchmark_mapping`:** a price file with **exactly one column**, and its
  mapping (phase 1.2).
  - **The column must be a total-return series** (`price_type = "total_return"`), because the
    portfolio's TWR includes the income received. A price index would make the portfolio look
    better by the dividend yield (methodology page *Benchmark mismatch*).
  - **An accumulating fund's price is a total-return series:** its mapping declares
    `total_return`, as the page will say.
- **`[parameters.benchmark]`,** with `name`: the text shown in the report, for example
  "MSCI ACWI IMI, net total return, in USD".
- **The input and the table go together:** one without the other raises.

### 2. The benchmark's value on each valuation date, in the base currency

For each date $d$ of the report's valuation:

$$B_d = L_{d'} \times x_{d''}$$

- $L_{d'}$ is the last benchmark level on or before $d$, no older than `max_price_age_days`,
  the limit that already applies to the prices.
- $x_{d''}$ is the ECB rate (base currency per unit of the benchmark's currency) on or before
  $d$, no older than `fx_max_age_days`. It is 1 when the benchmark is in the base currency.
- **Older values, or a benchmark in another currency without an `fx` input, raise** and name
  the date. Nothing is filled further than those limits, and the report lists every value it
  carried forward, as it does for the prices.
- **A currency-hedged index is declared in the currency it is hedged to,** so it is not
  converted twice.

### 3. The periods

- The comparison uses **the TWR periods between two valuation dates.** This is the rule 8.5
  used for the Sharpe ratio.
- **With `flow_timing = "start"`, the TWR also has a return on the first date.** It runs from
  the deposit to that day's close, and no benchmark return covers it, so it is left out of
  the comparison.
- For each period $t$: the portfolio return $r_t$ (the TWR), the benchmark return
  $b_t = B_t / B_{t-1} - 1$, and the active return $a_t = r_t - b_t$.

### 4. The measures

**Always** (any valuation frequency):

- the cumulative portfolio return $\prod (1 + r_t) - 1$, and the benchmark's over the same
  periods;
- their difference, in percentage points;
- **the window:** its first and last date and the number of periods.

**With `return_frequency = "monthly"`** (12 periods a year), from `qrlab.metrics.relative`:

- **The tracking error,** $s_a \sqrt{12}$, with `ddof = 1`.
- **The information ratio,** $12 \bar a / (s_a \sqrt{12})$.
- **Beta and alpha,** by `capm_regression`:
  - with an `estr` input (8.5): on the **excess returns** over the €STR of the same periods;
  - without it: on the plain returns, and the report says which.
  - Shown with: beta and its standard error, annualised alpha and its standard error, $R^2$
    and $n$.

**The conventions are written next to the numbers:**

- simple returns;
- $\sqrt{12}$ assumes no serial correlation;
- the OLS standard errors assume homoskedastic, uncorrelated errors;
- descriptive, not a test of skill.

**A measure that does not exist is shown as "not available" with its reason**, for example
fewer than 3 periods for the regression, or a zero tracking error.

### 5. Outputs

- **`benchmark.csv`,** one row per period: `portfolio`, `benchmark`, `active`, and with
  €STR `risk_free`, `excess_portfolio`, `excess_benchmark`.
- **The scalars,** when they exist:
  - `benchmark_total` and `active_total`;
  - `tracking_error` and `information_ratio`;
  - `beta`, `beta_se`, `alpha_annual`, `alpha_annual_se` and `r_squared`.

  All are tagged `descriptive`.
- **The report:** a new section, "Benchmark", in English and Italian. It sits after the
  performance section, and holds the table of the measures, the window and the conventions.
  Without a benchmark the section says that none was given.
- **The checks:** `CheckContext.benchmark_returns` gets $b_t$. So the `risk.beta` check runs,
  on plain returns as 2.4 defined it. The beta check on excess returns stays in IDEAS.
  - `require_same_index` would refuse a benchmark series without the first-date return. So,
    **when a benchmark is given,** the checks get both series on the periods between two
    valuation dates.
  - **Without a benchmark** the checks get the TWR exactly as today, first day included.
  - Whether the partial first day belongs in the other return checks is a separate question,
    added to IDEAS.

### 6. The API

- **Public, additive:** `build_portfolio_report` gains `benchmark: BenchmarkSummary | None =
  None`. It is an input added after the freeze, so it has a default (the rule of 11.1).
  `BenchmarkSummary` is a new frozen dataclass in `qrlab.reporting`.
- **No new metric:** the computation uses `qrlab.metrics.relative` as it is.

## Edge cases (each raises, naming the date or key)

- **The file's columns:** a benchmark file with no column or with more than one.
- **The series type:** a column that is not `total_return`; the message says how to declare an
  accumulating fund.
- **Staleness:** no level or rate within its limit on a valuation date.
- **Currency:** a benchmark not in the base currency, without an `fx` input.
- **Pairing:** `benchmark` without `[parameters.benchmark]`, or the reverse.
- **Fewer than two valuation dates** give no period: the section says so; the run does not
  fail.

## Outputs that change for configs without a benchmark

**Only `report.html`,** which gains the "Benchmark" section saying that none was given. No
number, table or scalar changes. Every output is checked byte for byte against `main` on the
example configs, and that section must be the only difference.

## Tests, hand-calculated first

1. **Three monthly periods.** Portfolio $r$ = (2, −1, 3) % and benchmark $b$ = (1, 0, 2) %, so
   $a$ = (1, −1, 1) %:
   - $\bar a = 1/3\,\%$, and $s_a = \sqrt{4/3}\,\% = 1.154701\,\%$;
   - **tracking error** $= \sqrt{4/3}\sqrt{12}\,\% = 4.00\,\%$;
   - **information ratio** $= (12 \times 1/3\,\%)/4\,\% = 1.00$;
   - **cumulative:** $1.02 \times 0.99 \times 1.03 - 1 = 4.0094\,\%$ against
     $1.01 \times 1.00 \times 1.02 - 1 = 3.02\,\%$, a difference of 0.9894 points;
   - **beta on plain returns:** $S_{xy} / S_{xx} = 4/2 = 2.0$; alpha $= 4/3 - 2 \times 1 =
     -2/3\,\%$ a month, $-8\,\%$ a year.
2. **A constant €STR** leaves beta unchanged and moves alpha by $r_f(1 - \beta)$. This is a
   property test against the hand case.
3. **Currency.** A USD benchmark at 100 → 110 while EUR/USD goes 1.25 → 1.10 is 80 → 100 in
   EUR: a +25 % return.
4. **Staleness:** a level carried forward within the limit is used and listed; one beyond it
   raises.
5. **The first date with `flow_timing = "start"`** is left out; with `"end"` there is no such
   return.
6. **The `risk.beta` check** becomes applicable with a benchmark. Without one, its result and
   the TWR the checks get are as today (a regression test).
7. **Each error above,** and the section in both languages.
8. **Cross-check** of tracking error and beta against `numpy.std` and `numpy.polyfit` on
   seeded data.

## Risks

- **A mismatched benchmark** (price index, wrong currency, a different universe) gives
  confident but meaningless numbers. Requiring `total_return` and converting with dated rates
  removes two of the three. The third is the owner's choice, so the report prints the
  benchmark's name and the methodology page *Benchmark mismatch* is linked from the section.
- **Short windows:** with a dozen monthly periods, beta and the information ratio are very
  noisy. The standard errors and $n$ are shown next to them, and nothing is called
  significant.

## Out of scope (in `IDEAS.md`)

- A benchmark per asset class, or a composite (weighted) benchmark.
- The `risk.beta` check on excess returns, and the partial first day in the return checks.
- Up and down capture in the report: the functions exist, so they are a small follow-up if
  wanted.

6–10 h, as planned.

## Results and deviations (2026-11-16)

- **Built as designed:**
  - `qrlab.experiments.kinds._portfolio_benchmark`, with `parse_benchmark`,
    `benchmark_series` and `compare`;
  - `qrlab.reporting.BenchmarkSummary` and the "Benchmark" section, in English and Italian;
  - the kind's inputs, outputs and scalars;
  - the checks' series.
- **Correction: the sign in test 2.** A constant risk-free rate $r_f$ moves alpha by
  $r_f(\beta - 1)$, not $r_f(1 - \beta)$: $\alpha' = (\bar y - r_f) - \beta(\bar x - r_f) =
  \alpha + r_f(\beta - 1)$. The test uses the right sign; with $\beta = 2$ and
  $r_f = 0.1\,\%$ a month, alpha moves from $-8\,\%$ to $-6.8\,\%$ a year.
- **Placement:** the section sits after the charts and before the look-through, since the
  summary is a single table.
- **Values carried forward** are listed in the report's data section as "Benchmark: level"
  or "Benchmark: USD rate", next to the prices and the valuation rates.
- **The kind test:** fund A alone, so the portfolio returns (2, −1, 3, 0) % against
  (1, 0, 2, 0) %:
  - tracking error $\sqrt{11}\,\% = 3.316625\,\%$;
  - information ratio $3/\sqrt{11} = 0.904534$;
  - beta $5/2.75 = 1.818182$;
  - the `risk.beta` check reports it as critical (above 1.50). Without a benchmark the check
    is not applicable, as before.
- **Tests:** 8 unit tests of the comparison, 9 report tests (including 6 parametrised error
  cases), 2 tests of the section's edge cases.
- **The gate:** 2590 tests on Python 3.13 and 3.11, with 100 % coverage; the docs and their
  doctests build.
- **Byte identity against `main`,** on the 8 example configs: the only difference is the
  two portfolio reports' new section, which says that no benchmark was given. Every other
  output is equal byte for byte.
