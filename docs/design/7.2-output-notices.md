# Design note — Phase 7.2: notices that travel with the outputs

Status: **approved 2026-11-14.** Deviations, if any, are listed at the end. Second of the
gap-closing phases (see 7.1).

## The problem

The `projection` kind writes its distribution of outcomes as CSV tables, a PNG fan chart and
`record.json`. None of these files says that the outcomes are **scenarios from stated
assumptions, not a forecast**. The "not a forecast" text exists only in the HTML portfolio
report, which the CLI and the app never produce for a projection.

A PNG or a CSV copied out of the output folder loses all context. The same is true, to a lesser
degree, of three other kinds whose outputs are easy to misread on their own:

| Kind | What a reader could wrongly take it for |
|---|---|
| `optimisation` | weights to hold, rather than an in-sample description of the method |
| `scenario_analysis` | a prediction of losses, rather than a "what if" on today's weights |
| `backtest` | expected performance, rather than one historical path |

A related gap: `sensitivity = false` is allowed in a projection config. In that case nothing in
the outputs says that no sensitivity analysis was run.

## Design

1. **`ExperimentOutput` gains `notice: str | None = None`.** This is a short plain-text notice
   that a kind writes for each run, so it can depend on the run; for example, it can say that
   sensitivity was switched off.
2. **The runner writes the notice** when it is not `None`:
   - to `NOTICE.txt` in the output folder, listed in `outputs` with the tag `descriptive`;
   - into `record.json` as a new top-level field, `"notice"` (`null` when there is none).

   The field is an addition, so `RECORD_FORMAT` stays 1, as the compatibility policy allows.
3. **The CLI prints the notice** after the status line of `qrlab run`.
4. **The app** shows the notice under the result's title.
5. **Figures carry it too.** `reporting.line_figure` gains an optional `note: str = ""`, drawn as
   a small footer line inside the PNG, so the notice survives when the image is copied. The new
   parameter has a default, so existing calls are unchanged. The projection fan chart uses it.

### The notices

| Kind | Notice |
|---|---|
| `projection` | "Scenarios from the stated assumptions, not a forecast. Outcomes are a distribution; no single path is expected." When `sensitivity = false`, it adds: "No sensitivity analysis was run for this projection." |
| `optimisation` | "In-sample weights: what this method does with these estimates. Not a forecast and not a recommendation." |
| `scenario_analysis` | "What-if stress tests on today's weights. Not forecasts or probabilities of loss." |
| `backtest` | "One historical path, with the stated costs, lag and taxes. Past results are not a forecast." |

- The other kinds (`portfolio_report`, `risk_report` and the studies) already carry their
  framing in an HTML report or in their sample tags; they get no notice.
- Every notice ends with "Research analytics, not investment advice."

## Compatibility

- `ExperimentOutput.notice` and `line_figure(note=...)` are additions with defaults. The API
  listing is updated (two signatures change).
- Existing records without `"notice"` stay valid; readers treat a missing field as `null`.
- `packaging/compare_runs.py` compares `NOTICE.txt` like any other output. Frozen and source
  runs are therefore still compared in full.

## Tests

- **Runner:**
  - a kind returning a notice yields `NOTICE.txt` with the exact text, an `outputs` entry
    tagged `descriptive`, and `record["notice"]`;
  - a kind without a notice yields no file and `"notice": null`.
- **Projection:**
  - the notice with sensitivity on, and the extra sentence with it off;
  - the fan chart differs from the one drawn without `note`, which shows the footer is drawn.
- **The three other kinds:** each example run has its notice in the record and in the file.
- **`line_figure`:**
  - with `note=""` the bytes are identical to today's, so existing figures do not change;
  - with a note, a valid PNG of the same size.
- **CLI:** `qrlab run` prints the notice.
- **App:** the results panel shows it. This is checked in the off-screen smoke test.
- **Byte-identical studies:** the study kinds get no notice, so a re-run of the studies must
  still match the published outputs byte for byte. I will run study 1 and study 3 again to
  confirm it.

## Risks

- **Notice text that overclaims or underclaims.** Each text is taken from the kind's own
  docstring, which states its framing today.
- **Clutter.** One short file and one footer line per run. The notices are not added to every
  kind, only where a lone output is easy to misread.
