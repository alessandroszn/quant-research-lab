# Design note — Phase 8.3: risk and stress tests in the `portfolio_report` kind

Status: **draft, waiting for approval.** Deviations, if any, are listed at the end. Third phase
of Level 8 (`docs/design/level-8-plan.md`).

## The problem

The portfolio report has a risk section, built from `qrlab.scenarios.RiskSummary`, with:

- volatility contributions;
- VaR and ES by method;
- stress tests.

The `portfolio_report` kind always passes `risk=None`, so the section only says that risk was
not computed. The `risk_report` and `scenario_analysis` kinds compute all of this, but from
separate returns files and weights typed by hand. Their numbers do not come from the
portfolio the report values, so the two can disagree.

## Design

Everything below is optional. Without `[parameters.risk]` the kind runs exactly as today,
byte for byte.

### Returns: from the report's own data

- **Position returns come from the price files the report already reads.**
  - All their dates are used, including those before the first purchase. A longer price file
    gives a longer window and covers past crises.
  - The prices are resampled to the chosen frequency by taking the last price in each period.
  - Missing prices are never filled.
- **Returns in the base currency.** A position priced in a foreign currency gets
  `(1 + r_local) × (1 + r_fx) − 1`. Here `r_fx` is the return of one unit of that currency in
  the base currency, from the `fx` input of 7.4a, on the same period ends and with the same
  `fx_max_age_days`.
- **Cash.** Base-currency cash returns 0. Foreign cash returns `r_fx`. Cash is part of the
  portfolio and of its risk.
- **Weights** are those of the check context on the last valuation date: positions and cash
  over the total value, summing to 1.
- **Dividends.** A price series of type `price` misses its dividends. The report then says,
  for each such position, that its return level is understated (as in 7.3). Volatility is
  barely affected.

### `[parameters.risk]`

| Key | Meaning |
|---|---|
| `frequency` | `"weekly"` or `"monthly"`: returns over the last price of each period. Checked against the price dates, so a monthly price file cannot give weekly returns. |
| `window` | Number of returns to use, ending on the last valuation date. If a position lacks them, the run fails and names the position and its first date. |
| `confidence` | VaR and ES confidence, e.g. `0.95`. |
| `covariance` | `{ estimator = "sample" }`, `"ewma"` (with `decay`, `demean`) or `"ledoit_wolf"`, as in `risk_report`. |

Daily returns are left out. Daily prices of ETFs from different exchanges and currencies are
not synchronous, and a daily window would understate correlations.

### What is computed (the existing library functions)

- **Covariance:** `estimate_covariance`. **Volatility contributions:**
  `volatility_contributions`, over positions and foreign cash.
- **Portfolio returns:** `Σ w_i r_i` over the window, at today's weights. This is a
  "what if today's portfolio had been held", not the TWR.
- **VaR and ES of the portfolio returns:**
  - historical;
  - normal;
  - Cornish-Fisher, shown as "not available", with the reason, when its expansion is not a
    quantile (as in `risk_report`).
- **Stress tests,** with an optional `scenarios` input (the TOML of `scenario_analysis`):
  - historical scenarios replay each position's own base-currency returns;
  - hypothetical scenarios apply their position and currency shocks.

  Factor shocks need betas, which this phase does not take: positions they would need are
  reported as "not covered", never as a 0 % loss.

### Outputs (only with `[parameters.risk]`)

- **The report's risk section,** with the window, the frequency and the number of returns
  stated, as it already does.
- **Tables:**
  - `risk_contributions.csv`;
  - `var_es.csv`;
  - `scenarios.csv` (with scenarios).

  All are tagged `descriptive`. Risk measured on history describes it; it does not forecast.
- **Scalars:**
  - `volatility_period` (one period);
  - `volatility_annual`, as `√P ×` the period figure, which assumes no autocorrelation, as the
    annualisation page says;
  - the historical VaR and ES.

## Tests (hand-calculated first)

- **Two positions, four monthly returns, weights 0.5 and 0.5, sample covariance:**
  - returns: a = (2, −1, 3, 0) % and b = (1, 1, −2, 0) %;
  - variances 3.333e-4 and 2.000e-4, covariance −1.667e-4;
  - portfolio variance 0.25 × 3.333e-4 + 0.25 × 2e-4 + 2 × 0.25 × (−1.667e-4) = 0.5e-4, so the
    volatility is 0.70711 %;
  - contributions 0.58926 % and 0.11785 %, shares 83.3 % and 16.7 %;
  - these values come out of the kind, from price files built to produce exactly these returns.
- **Currency:** a USD fund goes from 100 to 110 USD while EUR/USD goes from 1.25 to 1.10. The
  value in EUR moves from 80 to 100, a return of +25.0 %. That is
  `1.10 × 1.13636 − 1`, not +10 %.
- **Foreign cash:** 1,000 USD with the same rates returns +13.64 % in EUR. Base cash returns 0.
- **Resampling:** daily prices give month-end returns equal to the monthly price file's.
  A monthly file with `frequency = "weekly"` raises.
- **Errors:**
  - a window longer than a position's history raises and names the position;
  - `[parameters.risk]` without an `fx` input on a foreign position raises, as valuation does.
- **Scenarios:** a hypothetical −30 % position shock on a fund at 60 % gives −18 % by hand.
  A historical window before the price history is "not covered".
- **Byte identity:** configs without `[parameters.risk]` produce the same outputs as `main`.
  Studies 1 and 3 are re-run.

## Out of scope (IDEAS)

- **A VaR backtest in the report:** `risk_report` has one; the report stays descriptive.
- **Factor proxies (betas)** for positions without their own history.
- **Daily risk.**
- **Total-return series for distributing funds:** 8.7 and the dividends page.

## Risks

- **Short histories.** A fund bought recently has few returns. Asking for an explicit
  `window` and failing when it is not met keeps the number of returns visible; a VaR on 12
  monthly returns is stated as such, never presented as reliable.
- **Weights versus history.** The risk is that of today's weights applied to past returns. The
  report says so, and keeps it apart from the TWR.
