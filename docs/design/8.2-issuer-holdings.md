# Design note — Phase 8.2: issuer holdings as published (iShares and Vanguard)

Status: **approved 2026-11-14, with openpyxl.** Deviations, if any, are listed at the end. Second phase
of Level 8 (`docs/design/level-8-plan.md`). It runs before 8.1, which waits for the broker
exports; a one-ETF portfolio makes 8.1 short once they arrive.

## The problem

Look-through reads a fund's holdings through a declared mapping
(`qrlab.instruments.HoldingsCsvMapping`). Today that only works for files shaped like our
synthetic example. The owner holds an iShares ETF and plans a Vanguard one. Their published
files differ from the example in three ways that matter:

1. **Country names, not codes.** iShares writes "United States" in a "Location" column. The
   parser accepts only ISO 3166-1 alpha-2 codes, so a real file fails on its first row.
2. **The file format.** iShares publishes CSV with a preamble and quoted numbers such as
   "1,234.56". Vanguard's download is usually an Excel workbook, and the parser reads CSV
   only.
3. **Identifiers.** Some issuer files have no ISIN column. Securities are then keyed by name
   (`name:<name>`), and the same company may be spelt differently by two issuers ("APPLE INC"
   and "Apple Inc."). Overlap between an iShares and a Vanguard fund depends on this.

## Step 0: look at the real files first (you, about 5 minutes)

The layouts must come from the files as published today, not from memory.

- **What to download:** from each issuer's product page of the ETFs held, the holdings
  download. It is public and needs no login.
- **Where to put it:** `data/real/inputs/holdings/`, unchanged.
- **What I read:** only the header, the preamble and the footer, to write the mappings.
- **What gets committed:** none of the files' data. The test fixtures are synthetic files
  with the same headers and made-up holdings.
- **What step 0 decides:** the details of points 2 and 3 below, recorded as deviations if
  they differ from this note.

## Design

### 1. Country names (`qrlab.instruments.countries`)

- **`COUNTRY_NAMES`:** one English short name for each of the 249 codes in
  `qrlab.instruments.COUNTRIES`, following the ISO 3166-1 short names. A test checks that the
  two cover exactly the same codes.
- **`COUNTRY_ALIASES`:** spellings issuers use that differ from the ISO names, such as
  "United States" for "United States of America", "Korea (South)", "Taiwan", "Russia",
  "Vietnam" and "Turkey"/"Türkiye". Each alias points to exactly one code.
- **`country_code(name) -> str`:**
  - matching is exact after trimming spaces and ignoring case;
  - an unknown name raises and names the value;
  - nothing is fuzzy-matched or guessed.
- **Source check.** The ISO short names are checked once against the Python package
  `pycountry`, run temporarily with `uvx` and not added as a dependency. The result and the
  date go into the note's deviations.

### 2. Mapping changes (`HoldingsCsvMapping` and its TOML)

- **`country_format`** (required): `"iso_alpha2"` or `"name"`. A new required key, like 7.3,
  before 1.0 is released. `configs/csv_mappings/example_holdings.toml` declares
  `"iso_alpha2"`.
- **`country_values`** (optional table): the file's own wording mapped to a code or to
  `"unknown"`. Examples are `"European Union" = "unknown"` and `"Cash and/or Derivatives" =
  "unknown"`. It is checked before the built-in names, so a file-specific word is explicit.
- **`file_format`** (required): `"csv"` or `"xlsx"`. For `"xlsx"`, a required `sheet` (the
  sheet name) is read with the same `skip_rows`, columns, blank-line end and missing tokens.
  Numbers come from the cells directly; text cells are parsed with the declared separators.
- **New mapping files** `configs/csv_mappings/ishares_holdings.toml` and
  `vanguard_holdings.toml`, written from step 0.

### 3. Excel files: a new dependency (decision for you)

- **Recommended:** add **openpyxl**, used only to read `.xlsx` holdings files.
  - It is pure Python, MIT-licensed and the standard reader behind `pandas.read_excel`.
  - The reason goes in the commit and the CHANGELOG: Vanguard publishes holdings as Excel.
    Converting by hand is an unrecorded transformation of a raw file, and it can change
    numbers and dates.
- **Alternative:** no new dependency; you save the workbook as CSV and keep the original.
  This is simpler for the code but worse for provenance.

### 4. Identifiers and overlap across issuers

- A file with an ISIN column keys securities by ISIN, as today.
- Without one, the key stays `name:<name>`. Names are compared after normalising them:
  upper case, single spaces, and a fixed list of punctuation and legal suffixes removed (for
  example "INC", "CORP", "PLC", "LTD", "SA", "AG", "NV", "CLASS A").
  - The list is in the code and tested.
  - The look-through rows record which key was used.
- **The report states how good the matching is.** The overlap section shows the share of each
  fund's weight matched by ISIN and by name. A cross-issuer overlap built on names is labelled
  as approximate, never shown as exact.
- If step 0 shows that both files carry ISINs, this point shrinks to the label.

### 5. Issuer map (`qrlab.instruments.load_issuer_map`)

- **The file:** a CSV with exactly the columns `isin,issuer`, UTF-8, comma-separated.
- **Validation:** invalid ISINs, duplicates and empty issuers raise.
- **Use:** an optional input `issuers` in the `portfolio_report` kind, passed to
  `look_through`, which today always gets `None`. For an equity ETF it joins the share classes
  of one company, for example Alphabet A and C, in the issuer concentration check.
- **Without an ISIN column:** the map cannot apply, and the report says so.

### 6. Terms of use

- Before the mappings are committed, I review the terms of the iShares (BlackRock) and
  Vanguard websites for the holdings downloads.
- I record the decision in `docs/guides/data-sources.md`: files downloaded by you for personal
  analysis, read locally, never redistributed. qrlab has no download code for them.

## Tests (hand-calculated first)

- **Country names:**
  - `COUNTRY_NAMES` covers exactly `COUNTRIES`;
  - every alias resolves to a valid code;
  - "United States" gives US, "Korea (South)" gives KR, "UNITED KINGDOM " gives GB;
  - "Atlantis" raises.
- **iShares-layout fixture (synthetic):**
  - preamble, quoted thousands, a "Location" column, a "Cash and/or Derivatives" row mapped
    to unknown, and a disclaimer after a blank line;
  - with the fund at 60 %, the country exposures are worked by hand.
- **Vanguard-layout fixture:** a synthetic `.xlsx` written in the test with openpyxl (if
  approved), with the same hand case.
- **Name keys:** "Apple Inc." and "APPLE INC" give the same key; "Apple Hospitality REIT"
  does not. Two synthetic funds overlap by a known weight, computed by hand, with the matched
  share reported.
- **Issuer map:** two share classes of one issuer at 3 % and 2 % give an issuer exposure of
  5 % by hand, and 3 % without the map.
- **Kind:** the `issuers` input changes the `lookthrough.issuer` check as computed by hand.
  Configs without it run byte-identically.

## Out of scope

- Downloading holdings.
- Other issuers (Xtrackers, Amundi, SPDR): a mapping file each, when held.
- Fuzzy matching of names.
- Bond holdings details (duration, rating).

## Risks

- **Issuer layouts change without notice.** A changed header raises, because the columns are
  declared, never guessed. Updating the mapping file is enough.
- **Name matching is approximate by nature.** It is labelled as such, and the matched share
  is shown, so it can never pass for an exact overlap.
- **Real data.** The downloaded files stay in `data/real/`; the fixtures are synthetic.

## Deviations

### 8.2a: the reading layer, before step 0

The broker exports and the issuer files were not yet available, so the phase is split.

- **8.2a** contains everything that does not depend on the real files: points 1, 2, 4 and 5.
- **8.2b** contains the iShares and Vanguard mapping files and the terms review (point 6),
  from the files you download.

Further changes made in 8.2a:

- **Share classes are not stripped from names.** Point 4 listed "CLASS A" among the removed
  words. Removing it would merge two securities (Alphabet A and C) into one. The issuer map
  groups them as one issuer instead, which is the correct place.
- **Cash lines are never matched by name.** Without this, two funds' "Cash" lines would count
  as overlap.
- **The security key is unchanged.** Holdings without an ISIN keep `name:<name>` as their key
  in the look-through rows. Normalised names are used only to compare funds in the overlap.
  The duplicated-exposure measure still uses ISINs only, which is noted in IDEAS.
- **An issuers file needs holdings files**, and the kind refuses it otherwise.
- **The holdings mapping keys are required,** as decided for 7.3: the example mapping
  declares `file_format = "csv"` and `country_format = "iso_alpha2"`.
- **Byte-identity check.**
  - The `portfolio_report` example, run with the code of `main` and of this branch, is
    identical.
  - The full example's holdings mapping gained the two required keys, so `main` cannot read
    it. Run with `main`'s own copy of the mapping, its `exposures.csv`, `check_findings.csv`
    and scalars are identical to this branch's.
  - Studies 1 and 3 are identical.
- **Not verified:** the frozen Windows build with openpyxl. It is built in CI, after the next
  push.

### 8.2b: step 0 done (Vanguard only), the plan — approved 2026-11-15

**Terms of use (point 6), read on 2026-11-15.**

- **Vanguard.**

    pages for personal, informational and non-commercial use. Repeated automated access is
    forbidden.
  - The Italian fund documents point to the Irish website.
  - **Decision:** files downloaded by hand, for personal analysis, read locally, never
    redistributed.
- **iShares (BlackRock), Italian website.**
  - The website is for "personal and internal use", but "any copy of information or data"

    for personal use is not expressly allowed.
  - **Decision (yours, 2026-11-15):** no iShares mapping until the terms are clarified with
    BlackRock. This corrects the first look of 2026-11-15 in `docs/guides/data-sources.md`.

**The real files.** Both are from the FTSE All-World UCITS ETF page, exported by hand. They
stay in `data/real/inputs/` and are not committed.

| File | Layout |
|---|---|
| Holdings (xlsx, sheet "Holdings details") | 6 preamble rows, then the header `Ticker, Holding name, % of market value, Sector, Region, Market value, Shares`. 3,607 holdings, then a blank row and a disclaimer. Every number is text: `4.7436%`, `$4,239,627,231.84`, `12,301,968`. `Region` holds ISO alpha-2 codes (2 rows empty). There is no ISIN column, 10 rows have no sector and 20 no ticker. The weights add up to 98.77 %: cash and derivatives are omitted. |

The market price is empty before the listing date (16 Feb 2023), and one row has no NAV. |

**What the library cannot read today, and the changes proposed.**

1. **A symbol written next to a number** (`%`, `$`, `€`).
   - **Change:** a new required mapping key, `value_affixes`, in both mappings: the symbols
     removed from the start or the end of a number written as text. For example `["%"]` for
     the holdings and `["$"]` or `["€"]` for prices.
   - Any other character still raises, so nothing is guessed.
2. **Price files as xlsx, with a preamble** (`qrlab.data.CsvMapping`).
   - **Change:** new required keys, like the holdings mapping of 8.2a: `file_format`
     (`"csv"` or `"xlsx"`), `sheet`, and `skip_rows` (rows before the header).
   - The xlsx reading moves from `qrlab.instruments.io` to `qrlab.data`, so that both parsers
     share it; the layering allows instruments to use data, not the reverse.
   - **Existing price mappings** gain `file_format = "csv"`, `sheet = "none"`, `skip_rows = 0`
     and `value_affixes = []`. As in 8.2a, `main` cannot read the changed mappings, so the
     byte-identity check uses `main`'s own copies.
3. **Dates with English month names** (`%d %b %Y`).
   - **Change:** the date format may use `%b` for the month. English abbreviations (Jan–Dec)
     are read the same on every machine, never through the system's language settings.
4. **Two currencies in one file.**
   - **No change.** A price mapping has one currency, so the file gets two mappings: the
     market price in EUR (`price`) and the NAV in USD (`nav`).
   - For a fund bought on an EUR exchange, the report uses the EUR market price.

**Mapping files committed** (`configs/csv_mappings/`):

- `vanguard_holdings.toml`: the same for every Vanguard UCITS ETF with this layout.
  - columns `name = "Holding name"`, `weight = "% of market value"`, `country = "Region"`,
    `sector = "Sector"`;
  - `asset_class` fixed to equity (this file has no asset-class column);
  - `value_affixes = ["%"]`, `country_format = "iso_alpha2"`.
- `vanguard_prices_market_eur.toml` and `vanguard_prices_nav_usd.toml`: the instrument is
  the fund's ISIN. The committed files carry the synthetic ISIN of the examples, with a
  comment saying to replace it.

**Tests.**

- **Synthetic xlsx files with the same layout,** written by the tests with openpyxl and
  holding made-up securities and prices:
  - weights `4.7436%` give 0.047436;
  - a holding without a ticker, sector or region is kept;
  - the disclaimer after the blank row is ignored and counted;
  - prices come out in date order, with NaN where the market price is empty;
  - `$`/`€` are removed only where declared, and `13 Nov 2026` is read as 2026-11-13.
- **Errors:** an undeclared symbol, `%b` with a non-English month, a missing sheet and
  `skip_rows` beyond the end all raise.
- **The real files** are read once on this computer, outside the tests. I report row counts,
  weight sum and date range, never the data.
