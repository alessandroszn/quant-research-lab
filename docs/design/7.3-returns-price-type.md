# Design note — Phase 7.3: declare the price type of returns files

Status: **approved 2026-11-14.** Deviations, if any, are listed at the end. Third of
the gap-closing phases (see 7.1).

## The problem

User price files must declare a `price_type` for every column, and valuation and tracking
check it. The four kinds that read a CSV of **returns** do not: `backtest`, `optimisation`,
`risk_report` and `scenario_analysis` (its `position_returns` file). Nothing in their config
says whether the returns include dividends, and nothing in their outputs says it either. The
risk register's "total- vs. price-return flag required" is true for prices only.

The error is about the dividend yield every year. Here is an example by hand. A fund's price
goes from 100 to 102 in a year and it pays 3, so its total return is 5.0 % and its price
return is 2.0 %.

- **`backtest`:** cumulative and annualised returns are 3 points a year too low, so a strategy
  looks worse than holding a total-return index. Comparing it with a total-return benchmark is
  meaningless.
- **`optimisation`:** `mean_variance` and `maximum_sharpe` use mean returns, so price returns
  push the weights away from high-yield assets. The covariance-only methods (`equal_weights`,
  `minimum_variance`, risk parity, maximum diversification, HRP) are barely affected.
  Dividends add little variance.
- **`risk_report`:** volatility, correlations and contributions are barely affected. The mean
  enters the normal and Cornish-Fisher VaR, which come out a little worse.
- **`scenario_analysis`:** a historical replay of a position misses the dividends over the
  window. This is small for a short crisis and larger for a long one.

## Design

1. **A new required key that declares the series type.**
   - `backtest`, `optimisation` and `risk_report` get `returns_price_type`.
   - `scenario_analysis` gets `position_returns_price_type`. It is required always, like the
     existing `position_returns_currency`.
   - Values: `"total_return"` (dividends included) or `"price"` (dividends excluded). One value
     covers the whole file.
2. **`"nav"` is refused** with a message that says what to use instead. A NAV return includes
   the income for an accumulating fund (declare `total_return`) but not for a distributing one
   (declare `price`). The NAV alone does not say which.
3. **Shared parsing.** A `price_type(parameters, key)` helper in `kinds/_frames.py` returns a
   `qrlab.data.PriceType`. An unknown or missing value raises when the config is validated,
   before any data is read. The error names the allowed values.
4. **The declaration travels with the outputs**, through the notice mechanism of 7.2.
   - With `"price"`, every one of the four kinds adds this sentence to its notice, before the
     closing "Research analytics, not investment advice.": "Returns declared as price returns
     (dividends excluded): return levels are understated by about the dividend yield;
     volatilities and correlations are barely affected."
   - `risk_report` has no notice today. It gets one only in that case: the sentence plus
     "Research analytics, not investment advice."
   - With `"total_return"`, the notices are unchanged.
   - The declaration itself is in the record already, because the record stores the config
     text.
5. **Templates and examples.**
   - The app's "New from template" lists every required key, so the new key appears there.
   - The four example configs declare `"total_return"`. Their synthetic returns are meant to
     be total returns.
   - The guide `docs/guides/kinds.md` lists the new keys.

## Compatibility

- **A new required key.** The compatibility policy treats a new required config key as a
  major change. Version 1.0.0 is not released yet: only `1.0.0rc1` exists, locally and with no
  tag. So this is the last moment to add it without a 2.0.
  - Configs written for 1.0.0rc1 for these four kinds must add one line.
  - The error says which line.
  - The CHANGELOG says it under "Changed".
- **Optional instead of required (rejected).** With a default it would be compatible, but the
  project rule is that conventions are explicit, never silent defaults. A default of
  `total_return` is exactly the silent assumption this phase removes.
- **Records:** no new field. `RECORD_FORMAT` stays 1.
- **Studies:** the study kinds read Ken French and OSAP data, whose returns include dividends
  by construction, so they are unchanged. Studies 1 and 3 are re-run to confirm byte identity.

## Tests

- **Parsing:**
  - `"total_return"` and `"price"` are read;
  - `"nav"` raises, and the message suggests `total_return` for an accumulating fund and
    `price` for a distributing one;
  - an unknown value or a missing key raises at validation and names the key.
- **For each of the four kinds:**
  - with `"total_return"`, the notice is the 7.2 notice exactly;
  - with `"price"`, the notice contains the price-return sentence, before the closing
    sentence.
- **`risk_report`:** no notice with `"total_return"`; with `"price"`, exactly the sentence
  plus the closing sentence.
- **Numbers do not change.** For each kind, the same returns file run with either declaration
  gives byte-identical tables and scalars. The declaration labels the data; it does not
  transform it.
- **Template:** `config_template` for the four kinds contains the new key.
- **Examples:** the four example configs still run.

## Limits (to be written in the methodology page)

- **The declaration is trusted.** qrlab cannot tell from a returns file whether dividends are
  included. A file that mixes total-return and price-return columns, declared as one type, is
  not detected.
- **Nothing is converted.** No dividend yield is added to price returns. That would need dated
  dividend data, which the kinds do not take.
- **Factor and FX files are not covered.** The `factors` and `fx` inputs of
  `scenario_analysis` get no declaration. Factor returns such as Fama-French already include
  dividends, and currency returns have none.
- **Taxes in the backtest.** The `backtest` taxes realised capital gains only. With total
  returns, reinvested dividends are taxed as part of the gain when sold, as for an
  accumulating fund. Dividends paid out and taxed each year (a distributing fund) are not
  modelled.

## Risks

- **Breaking existing configs.** This is limited to the four kinds and caught at validation,
  before any run, with an exact message. The example configs and tests are updated in the same
  change.
- **A too-alarming sentence.** The sentence states the direction and size of the bias ("about
  the dividend yield") and what is barely affected, rather than calling the results invalid.

## Effort

About 2–3 h. Done locally on its own branch and merged into local `main` after your OK.

## Deviations

- **`scenario_analysis` without `position_returns`.** The design says every kind adds the
  price-return sentence with `"price"`. A scenario run without the optional `position_returns`
  file reads no returns of that type, so the sentence would be wrong there. It is added only
  when the file is given (`test_no_position_returns_no_price_sentence`). The key stays required
  in both cases, as designed.
- **Notice constants.** The kinds' `NOTICE` constants of 7.2 became `CAVEATS` (without the
  closing sentence). `kinds._frames.returns_notice` adds the price-return sentence when it
  applies, then "Research analytics, not investment advice.". The notice texts with
  `"total_return"` are exactly those of 7.2. These module constants are not public API.
- **Byte-identity check.** Studies 1 (three runs) and 3 (two runs) were re-run from unchanged
  configs in a temporary folder with copies of their `trials.jsonl`; `packaging/compare_runs.py`
  reports both identical to `results/studies`.
