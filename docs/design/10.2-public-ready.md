# Design note 10.2 — ready to be read by others

Status: **approved 2026-11-16; the owner chose A for the e-mail address.** Second phase of Level 10 (`docs/design/levels-10-13-plan.md`).

## Why

Making the repository public is one-way:

- every version of every file becomes readable;
- so does every commit's metadata, and everything GitHub keeps beside the history (pull
  requests and their commits).

This phase checks all of it before anyone can read it. It also brings the public texts up to
date with Levels 8 and 9. Nothing here changes a result.

## 1. A finding that needs the owner's decision: the e-mail address in the commits

| Identity in the history | Author or committer entries |
|---|---|
| The owner's personal Gmail address | 264 |
| The owner's GitHub `noreply` address | 266 |
| GitHub's own `noreply` (merges made on the website) | 66 |

`scripts/audit_history.py` does not see this. It reads every file version, but not the
commits' author and committer fields, nor their messages.

Once public, anyone can read the personal address: `git log` on a clone, or `.patch` at the
end of any commit URL. There are three ways:

- **A. Rewrite, then publish in a fresh repository** (recommended).
  - **Rewrite:** git's own `filter-branch` (no new tool) replaces the personal address with the
    `noreply` one in every commit, locally. Content and dates are unchanged.
  - **The catch:** every commit hash changes, and so do the four tags `v0.1.0`–`v0.4.0`.
  - **Why not force-push the old repository:** a force-push does not clean it, because GitHub
    keeps each pull request's original commits (`refs/pull/*`) with the old address. So the
    rewritten history goes to a **new** repository, with the same name once the old one is
    renamed (for example `quant-research-lab-private-archive`) and left private.
  - **The cost:** the 67 pull requests and their CI history stay in the private archive.
  - **Who does what:** the owner renames and creates the repositories; I only rewrite locally
    and verify.
- **B. Keep the history as it is** and accept that the address is public.
- **C. Publish one squashed commit.** It loses the whole history. Not recommended: the
  history is part of the project's reproducibility (each run records its commit).

Whatever the choice, from now on this checkout commits with the `noreply` address: a
repository-level `git config user.email`, with the owner's OK. Two GitHub settings are the
owner's to turn on: *Keep my email addresses private* and *Block command line pushes that
expose my email*.

## 2. The audit also reads the commits

`scripts/audit_history.py` gains a second pass over every commit reachable from any ref:

- **Author and committer e-mails** other than the allowed ones are reported. The allowed ones
  are GitHub's `noreply` addresses and `example.com`/`example.org`.
- **Commit messages** go through the same checks as file contents: secrets, IBANs, e-mails,
  and the real portfolio's ISINs.
- **`noreply@anthropic.com`** is allowed explicitly. It appears in the `Co-Authored-By`
  trailers by design.
- **As before,** the report gives counts and commit hashes, never values.
- **Tests:** a synthetic repository with a commit by `someone@private.test`, and one whose
  message holds a fake secret. Each must be reported without its value, and the clean
  repository must still pass.

## 3. Running it on `data/`, and reading the findings

The ISIN check takes its list from every file under `data/`, but `data/real` today holds
issuer files, Vanguard's and iShares', with thousands of public securities. So:

- **An ISIN finding** may be a public security named in a test or a guide, not a leak.
  Each path is reviewed and reported to the owner, as a path and a count.
- **Personal data.** Only a finding that could be personal (an e-mail, an IBAN, a file under
  `data/`, a spreadsheet, a secret) blocks publication until it is resolved.
- **The funds named in the files.** The mappings and the 8.2 note name the two funds used as
  format examples (iShares Core MSCI World, Vanguard FTSE All-World). The iShares ISIN has also
  been a sample ISIN in tests since 1.3. They are public funds, but naming them shows which
  funds the owner looked at. The owner decides whether they stay or become placeholders.

The audit runs twice: now on the current history, and again in 10.3 on the history that is
actually published, rewritten or not, which must end with `CLEAN`.

## What it delivers

- the extended audit with its tests;
- the README, ROADMAP and other texts updated;
- the notice test;
- the audit's findings, reported as paths and counts;
- the owner's decision on the e-mail, recorded in this note.

If the decision is A, the local rewrite is done in 10.3, right before the first push, so that
nothing is rewritten twice.

## Edge cases and risks

- **Rewriting (A)** changes every hash that a run record or document quotes. The run records
  under `data/` are not in git. Documents that quote a hash (design notes, CHANGELOG) keep the
  old one; a mapping old → new is written into the rewrite's own note.
- **Nothing is deleted.** The private archive keeps the old history intact.

## Effort

4–8 h, plus 1–2 h for the rewrite in 10.3 if A is chosen.

## Results and deviations (2026-11-16)

- **The audit, extended and run** with the ISINs under `data/`:
  - **Scope:** 1,308 file versions, 302 commits and annotated tags.
  - **Clean:** no secrets, no file under `data/`, no spreadsheet, no CSV outside `examples/`
    and `tests/`, nothing in any commit or tag message.
  - **E-mail:** 136 commits and tags carry another address. It is always the same one, the
    owner's personal address: 264 author and committer entries, plus the tagger of the four
    tags. The rewrite (A) resolves it in 10.3. The four tags are separate objects and are
    re-created with the `noreply` address too.
  - **ISINs:** `data/` holds one valid ISIN, the public example fund's. It is in four files
    (the 1.3 note and three tests) and has been the sample ISIN since 1.3. It stays, as a
    public fund named as an example.
  - **The audit's own test file** holds a documentation IBAN and invented e-mail addresses,
    so that it can test the audit. It is reported every time, and it is reviewed: synthetic.
    So the audit cannot print `CLEAN` on this history, and `releasing.md` now names this one
    accepted exception.
- **Deviation: personal details in three design notes.** The search for this note found three
  sentences about the owner's own situation: the 8.6 note named the owner's brokers, the 8.7
  note said what kind of ETF the owner holds, and the 8.2 note named their issuers.
  - **Now:** they are rewritten in general terms.

  - **The old wording** is kept only in the git-ignored `data/publication/`, for the rewrite.
  - **No commit message** mentions them.
