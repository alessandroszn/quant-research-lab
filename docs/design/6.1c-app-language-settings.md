# Design note — Phase 6.1c: Italian interface, settings and polish

Status: **approved 2026-11-13.** Deviations, if any, are listed at the end. This completes phase 6.1; the 6.1 note
(`6.1-desktop-app.md`) stays the reference for everything not changed here.

## Goal

The third and last PR of phase 6.1:

1. **Italian interface.**
2. **Numbers and dates** shown in the chosen language's conventions.
3. **A Settings screen**, saved between sessions.
4. **Recent workspaces** on the Home screen.
5. **A short list of fixes** that protect the user's work.

As before, the app contains no financial logic. One small, pure formatting function is added to
`qrlab.reporting.formatting`, which the app may already import.

## 1. Language

### What is translated

- **The app's strings** (`strings.py`):
  - an `it` table with exactly the same keys and `{placeholders}` as `en`, checked by a test;
  - `LANGUAGES = ("en", "it")`;
  - the app language maps to `reporting.formatting.Language`.
- **The app's own error messages:**
  - today they are English text raised by the view-models, for example "no config is
    selected";
  - `AppError` will carry a string key and its values instead, and the screen translates
    them.
- **Sample tags and run status:**

  | Value | English | Italian |
  |---|---|---|
  | `in_sample` | in-sample | in campione |
  | `out_of_sample` | out-of-sample | fuori campione |
  | `descriptive` | descriptive | descrittivo |
  | `completed` | completed | completato |
  | `failed` | failed | fallito |

### What is **not** translated

These are identifiers that must match what is on disk and what the CLI prints:

- the runner's and library's validation messages, which stay verbatim, as approved in 6.1
  (the same choice as "Translate not-applicable reasons" in `docs/IDEAS.md`);
- kind names;
- config and output file names;
- output table names and their column names;
- scalar names;
- the TOML in the editor (TOML always uses a decimal point).

The portfolio report keeps its own `language` parameter in the config. The app does not
override it, so a CLI run and an app run of the same config stay identical.

### Default and switching

- **At first start:** the app uses Italian if the system locale's language is Italian, and
  English otherwise. After that it uses the saved setting.
- **Unrecognised saved value:** if the setting holds a language the app does not know, the
  default above applies, and the Settings screen shows the language actually in use.
- **When a change takes effect:** immediately. The main window is rebuilt in the new language,
  keeping the open workspace and the current screen.
- **During a run:** switching is refused with a message, because the run's worker is attached
  to the current window.
- **Unsaved edits:** they go through the guard in §5 first.

## 2. Numbers and dates on screen

### New library function

`reporting.formatting.format_significant(value, digits, *, style) -> str`

- Rounds to `digits` significant figures, half-up on the decimal value of the float, the same
  as `format_number`.
- If `1e-4 <= |x| < 1e12`, or `x == 0`: fixed notation with thousands grouping and trailing
  zeros removed.
- Otherwise: scientific notation with the style's decimal separator.
- Negative zero is shown as `0`.
- Non-finite numbers raise, as in `format_number`. The display layer below decides how to show
  them.

**Hand-calculated examples** (6 significant figures; EN / IT):

| Value | EN | IT | Why |
|---|---|---|---|
| `0.0317` | `0.0317` | `0,0317` | trailing zeros removed |
| `0.333333333` | `0.333333` | `0,333333` | 6 significant figures |
| `1234567.891` | `1,234,570` | `1.234.570` | 1234567.891 → 1234570, grouped |
| `-22500.0` | `-22,500` | `-22.500` | grouped, no decimals |
| `1.000005` | `1.00001` | `1,00001` | half-up on the decimal value |
| `0.0` and `-0.0` | `0` | `0` | negative zero shown as 0 |
| `2.5e-05` | `2.5e-05` | `2,5e-05` | below `1e-4`: scientific |
| `3.2e12` | `3.2e+12` | `3,2e+12` | `1e12` or above: scientific |

### Display rules in the app

- **Floats** in result tables, scalars, and the Data and History screens use
  `format_significant` with 6 significant figures. This replaces today's `f"{x:.6g}"`, which
  ignores the language.
- **Missing values** (NaN) are shown as `—` in both languages; today the app shows `nan`.
  Infinities are shown as `∞` and `-∞`.
- **Integers** are shown as they are, without grouping. In these tables they are counts,
  windows or years, and `2.024` for a year would be wrong.
- **Text cells,** including the dates in output tables, are shown exactly as the CSV has them.
  The app does not guess which text columns are dates.
- **Dates the app itself shows** use `format_date`, which gives `12/11/2026` in Italian and
  `2026-11-12` in English:
  - Data screen: retrieval date;
  - History screen: end time, with the time `HH:MM UTC`, because records are stored in UTC.

The files on disk never change: formatting is for display only.

## 3. Settings

### Settings screen

A new **Settings** screen ("Impostazioni") is added as the last item in the navigation. It
has:

- the language: English or Italiano;
- the list of recent workspaces, with *Remove* and *Clear*;
- an *About* box:
  - app version (read from `importlib.metadata`, so no import outside the allowed layers);
  - Python and Qt versions;
  - the disclaimer.

### What is stored

- the language;
- up to **8 recent workspaces**, most recent first, with no duplicates (compared by resolved
  path);
- the window size and position.

Nothing else is stored: no portfolio data, no file contents, no history.

### Where it is stored

- **Format:** `QSettings` in **INI format**, not the Windows registry. The user can read and
  delete it, and the 6.2 uninstaller can remove it.
- **Location:** the user's configuration folder, which on Windows is
  `%APPDATA%\qrlab\qrlab-app.ini`.
- **Contents:** workspace paths reveal folder names, so they stay on the user's machine only,
  like the rest of the app (no network, no telemetry).

### Testability

- The view-model (`SettingsViewModel`) reads and writes through a small `SettingsStore`
  protocol (`get`/`set` of strings).
- Tests use an in-memory store. A separate test checks the `QSettings` adapter against an INI
  file in `tmp_path`, so tests never touch the real user settings.

## 4. Home screen

- **Recent workspaces:** the screen lists them, and a click opens one.
- **Missing folder:** if a recent workspace folder no longer exists, it is shown greyed out
  with "not found" and is not opened. It stays in the list until the user removes it.
- **Recording:** opening or creating a workspace records it as the most recent.
- **Window title:** shows the workspace folder's name.

## 5. Fixes that protect the user's work

1. **Unsaved edits.** Today, selecting another config, creating or duplicating a config, or
   closing the window silently discards unsaved changes in the editor.
   - The view-model will track whether the editor text differs from the file.
   - Those actions will first ask *Save / Discard / Cancel* through the injected dialogs.
   - *Validate* and *Run* already save first; that is unchanged.
2. **Closing during a run.** The runner cannot be cancelled (6.1). Closing the window while a
   run is in progress is refused with a message that says so, rather than leaving a half-written
   output folder.
3. **Shortcuts:** `Ctrl+S` saves the config and `F5` refreshes the current screen.
4. **Editor:** monospace font and no line wrapping, so TOML tables and columns line up.

Form editing, cancellation and interactive charts stay in `docs/IDEAS.md`. They are not in this
PR.

## Tests

- **`format_significant`:**
  - every row of the table in §2;
  - rejects `digits` outside 1 to 15, booleans and non-finite values;
  - cross-check on a seeded sample of floats away from ties: the output, read back as a number
    after removing the separators, equals `float(f"{x:.{digits}g}")`.
    - Only the value is compared, not the text, because Python's `g` switches to scientific
      notation from `1e6`.
- **Strings:**
  - `en` and `it` have identical key sets and identical placeholders per key;
  - no empty strings;
  - `tr` with an unknown language still raises.
- **`AppError` keys:** every key raised by a view-model exists in both tables. A test triggers
  each error and translates it.
- **`SettingsViewModel`**, in-memory store:
  - default language from a given locale;
  - an unknown saved language falls back to the default;
  - recents are ordered, deduplicated, capped at 8, and can be removed or cleared;
  - a missing folder is marked.
- **`QSettings` adapter:** a round trip through an INI file in `tmp_path`.
- **Editor dirty state:** after `set_text` with new text, the editor is dirty; after save or
  select, it is clean; setting the same text back makes it clean again.
- **Off-screen smoke test** (extended):
  - switch to Italian, then check the navigation reads "Impostazioni" and the workspace stays
    open;
  - a result table shows `0,0317` and `—`;
  - unsaved edits trigger the *Save / Discard / Cancel* question, and each answer does what it
    says;
  - closing during a run is refused;
  - the Home screen opens a recent workspace.
- **Layering:** unchanged; `qrlab_app` still imports only `qrlab.experiments` and
  `qrlab.reporting`.

## Risks

- **Translation quality.** The Italian strings are mine. You read Italian, so the PR will list
  them all side by side with the English for a quick review.
- **Rebuilding the window on a language change.** Every screen must reload from the view-models.
  That is already true, because screens hold no state the view-models lack, and the smoke test
  checks it.
- **`QSettings` on Linux CI.** It writes under the home folder unless redirected. Tests always
  pass an explicit INI path.
