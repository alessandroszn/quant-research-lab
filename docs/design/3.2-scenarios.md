# Design note — Phase 3.2 `qrlab.scenarios`: stress tests

Status: **approved 2026-11-11.** Deviations, if any, are listed at the end.

## Goal

Show what the **current** portfolio would lose in named scenarios, with every assumption
visible:

- **historical replays:** the returns of a past window, such as the 2008 crisis, the 2020 Covid
  crash or the 2022 rate shock, applied to today's holdings;
- **hypothetical shocks:** user-defined moves of factors, single positions and exchange rates,
  mapped to positions through estimated sensitivities;
- **report section:** "Risk and stress tests" in the portfolio report. It shows the 3.1
  numbers for volatility, contributions and VaR/ES, plus the scenario results.

A stress test is a "what if" on today's weights. It is **not** a forecast or a probability, and
the report says so.

## Inputs

- **Portfolio:** weights by position and cash weights by currency on `as_of`, as in 2.4 and 2.5,
  and the exposure currency of each position (its hedge currency if hedged).
- **Return series** come from the caller, at an explicit, regular frequency:
  - per position, where its own history covers the window (a price, NAV or total-return
    series turned into simple returns, with the type shown);
  - per factor (for example Ken French market factors, or a user CSV of a bond or equity
    index);
  - per exchange rate, as ECB rates turned into base-currency returns.
- **Factor model:** betas per position from 3.1 (`fit_factor_model`), estimated on a stated
  window. Ready-made betas from the user are also accepted.
- **Scenario definitions** come from TOML in `configs/scenarios/`:
  - a historical scenario has a name, a description and the dates `start` and `end`; it
    covers returns dated in $(\text{start}, \text{end}]$;
  - a hypothetical scenario has factor shocks, position shocks and currency shocks, each a
    simple return such as `market = -0.30` or `USD = -0.10`.

  The shipped files are **example definitions**. The historical dates follow commonly cited
  peak-to-trough dates of the S&P 500:
  - 2007-10-09 to 2009-03-09;
  - 2020-02-19 to 2020-03-23;
  - 2021-12-31 to 2022-10-12 for the 2022 rate shock.

  They are editable, not recommendations.

## Definitions

- **Position return in a historical replay.** Each position is treated by the first method that
  applies, and the method is shown per position:
  1. **direct:** its own return series covers every period of the window, so
     $R_i = \prod_t (1 + r_{i,t}) - 1$;
  2. **proxy:** it has betas, and the factor series cover the window. Each period is mapped
     first, as $r_{i,t} = \beta_i^\top f_t$ with no alpha and no residual, and the results are
     compounded, $R_i = \prod_t(1+r_{i,t}) - 1$;
  3. **not covered:** its weight is reported, and the portfolio figure is given for the covered
     part only. A missing position is never assumed to lose 0.
- **Currency.**
  - A position whose exposure currency $c$ differs from the base currency has base return
    $(1+R_i)(1+X_c) - 1$, where $X_c$ is the change over the window in the value of one unit
    of $c$ in the base currency.
  - Foreign cash has return $X_c$.
  - Hedged share classes take $X$ of their hedge currency, so a class hedged to the base
    currency has $X = 0$.
  - A direct series already in the base currency (for example a EUR NAV of a USD fund) is used
    as it is. The series currency is an explicit input, so the currency effect is never counted
    twice.
- **Hypothetical shocks.**
  - A factor shock $F$ gives $R_i = \beta_i^\top F$ (one period, linear).
  - A position shock replaces $R_i$ for that position.
  - A currency shock sets $X_c$.
  - Factors that are not shocked are 0. Correlated moves are not implied: the user states
    every shock explicitly.
- **Portfolio result:** $R_p = \sum_i w_i R^{base}_i + \sum_c w_c X_c$, and the loss in money is
  $R_p \times$ the portfolio value on `as_of`. The output also includes:
  - the contribution of each position, $w_i R^{base}_i$;
  - the coverage, meaning the weight that is not covered;
  - the first and last observation dates actually used.
- **Frequency.** The window is applied to the observations of each series. With monthly data,
  a 23-day crash falls inside one or two months, so its size depends on month-ends. The
  effective dates are always reported.

## Report section "Risk and stress tests"

This section is an optional input of `build_portfolio_report`: `None` writes "not computed",
as for checks and look-through.

- **Risk:**
  - volatility and its contributions by position;
  - VaR and ES at a stated confidence by the four 3.1 methods;
  - the window and the frequency.
- **Scenarios:** one row per scenario, showing:
  - the portfolio return and the loss in money;
  - the coverage;
  - the dates used;
  - the method by position (in a detail table).
- A note says that stress tests are "what if" analyses on today's weights, not forecasts, and
  that proxy replays ignore specific risk.

## Hand-calculated tests

| Case | Expected |
|---|---|
| Position A at 60 %, cash 40 % (EUR); A falls 30 % | $R_p$ = −18 %; contribution of A −18 % |
| Single position, shock $s$, weight $w$ | $R_p = w s$ (roadmap test) |
| USD position at 50 %, local −10 %, USD −5 % against EUR | base return 0.9 × 0.95 − 1 = −14.5 %; $R_p$ = −7.25 % |
| Same position hedged to EUR | base return −10 %; $R_p$ = −5 % |
| USD cash at 20 %, USD −5 % | contribution −1 % |
| Proxy, β = 1.2, market −10 % then −10 % | per period −12 %; $R$ = 1 − 0.88² = −22.56 % (not −22.8 % from the cumulative −19 %) |
| Asset returns built exactly as β f | proxy replay = direct replay (roadmap consistency test) |
| Position without history or betas at 25 % | not covered 25 %; $R_p$ over the other 75 % only, labelled |
| Hypothetical market −30 %, β 0.8 and 1.1 at weights 0.5 and 0.3 | −0.5·0.24 − 0.3·0.33 = −21.9 % |

## Edge cases

- **Windows:** a window with no observations (raises); a window that starts before a series
  does (that position falls back to proxy, or is not covered); `end` before `start` (raises);
  a window after `as_of` (allowed: replays need not precede `as_of`).
- **Data:** missing values inside the window (the series does not cover the window, never
  forward-filled); a cash-only portfolio; an unknown factor name in a shock (raises); a shock
  of −100 % or below (raises).

## Risks

- **Proxy replays understate risk.** Without the residual, specific risk is missing, and
  betas estimated in calm periods understate crisis co-movement. The report labels proxy rows,
  and the method is always visible.
- **Survivorship and history.** ETFs launched after 2008 have no own history, so for them the
  2008 replay is a proxy by construction.
- **Factor coverage.** Ken French factors are US-based. For European holdings a user index
  series is the better proxy, and the note on the report names the factors used.
- **No implied correlations** in hypothetical shocks. That is deliberate: a joint shock must be
  written down.

## Deviations from the approved note

Found while implementing; none changes a definition or a hand value.

- **One example file.** The historical and hypothetical scenarios share
  `configs/scenarios/example.toml`. Each scenario is a table with a `kind`. A hypothetical
  scenario must list all three shock tables, even when they are empty.
- **Currency of a direct replay.** The note asked for an explicit series currency. The
  currency effect applied is that of the **series** currency, so a series in the base currency
  gets none. Proxy replays apply the effect of the position's exposure currency.
- **Hypothetical shocks with currencies only.** When a scenario has no factor shocks, every
  position without its own shock is labelled "currency only", with local return 0, whether or
  not it has betas.
- **Missing exchange rates.** A foreign position or cash balance without exchange rates covering
  the window is "not covered", with a note. It is never treated as if the currency did not move.
- **Report input.** `RiskSummary` (in `scenarios`) bundles:
  - the volatility contributions;
  - the VaR and ES figures by method;
  - the scenario results;
  - the estimation window, frequency and confidence.

  It refuses an estimation window that ends after `as_of`.
- **Example.** `examples/risk_models.py` runs the example scenarios on synthetic data starting
  in 2020. The 2008 replay is therefore not covered except for cash, which shows how coverage
  is reported. The HTML report example keeps `risk=None`: three toy months are too few for
  the risk figures.
