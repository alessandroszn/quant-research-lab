# Design note — Phase 2.3 `qrlab.reporting` v1

Status: **draft, awaiting approval**. No code is written until this note is approved.

## Goal

The first visible deliverable: a **self-contained HTML report** of a portfolio, built only from
the library's verified results (ledger, valuation, TWR, MWR, P&L, metrics). It must be honest
about what it shows. Every report states:

- the as-of dates of its data;
- the provenance of every input file;
- the assumptions used (flow timing, cost basis, FX source, staleness limits);
- every carried-forward price or rate;
- a "not investment advice" notice.

The report computes nothing new. Formatting and layout only; all numbers come from tested
functions.

## Layering

`reporting` is layer 6. It already may import `core, data, stats, metrics, validation,
backtest`; `instruments` and `portfolio` are added to `ALLOWED["reporting"]` (both lower
layers).

## Scope

| Module | Contents |
|---|---|
| `reporting/formatting.py` | `NumberStyle` (decimal and thousands separators), formatting of numbers, percentages, money and dates; HTML escaping |
| `reporting/tables.py` | `Table` (title, columns, rows, notes) and builders for positions, P&L, performance, data sources |
| `reporting/figures.py` | Matplotlib (Agg) figures as PNG bytes: portfolio value with flows, cumulative TWR, drawdown |
| `reporting/html.py` | Rendering of a `Report` into one HTML file: inline CSS, figures embedded as base64, no external resources |
| `reporting/portfolio_report.py` | `build_portfolio_report(...)` from ledger, valuation and inputs; `write_report(report, path)` |

## Decisions

1. **Language: Italian or English, chosen per report** (`language="it"` or `"en"`, required).
   A small fixed dictionary holds the labels; no translation library. Number style follows
   the language (Italian `1.234,56` and `3,17 %`; English `1,234.56` and `3.17%`) unless
   overridden.
2. **Self-contained and private by construction:**
   - no CDN, web fonts, scripts or links to external resources;
   - figures are embedded;
   - an automated test checks the HTML contains no `http://` or `https://` references (other
     than an optional link to the ECB terms, which is in plain text, not a fetched resource).
3. **Output location is explicit.** `write_report(report, path)` takes a full path. The
   example writes under `results/`, which is git-ignored, like `reports/` and `data/`. Real
   portfolio reports must never be committed: this is restated in the report's footer and in
   the docstring.
4. **Deterministic output:**
   - the same inputs produce byte-identical HTML;
   - PNG metadata (software, creation time) is stripped, the DPI and figure size are fixed,
     and a single bundled Matplotlib font (DejaVu Sans) is used;
   - the generation timestamp is an explicit argument, `generated_at`, never `now()` inside
     the library.
5. **What the v1 portfolio report contains:**
   - **header:** portfolio name, base currency, period, generated-at, as-of date of the latest
     valuation;
   - **summary:** end value; net external flows; P&L; **TWR** for the period (and annualised
     only if the period is at least one year, by the explicit rule
     $(1+TWR)^{365/\text{days}} - 1$); **MWR (XIRR)**, with a warning if the root is not
     unique; maximum drawdown of the TWR path;
   - **TWR and MWR are shown in separate rows with their definitions** and the sentence "they
     measure different things".
   - **Volatility and Sharpe** only if the caller declares the return frequency and
     `periods_per_year`. Otherwise they are omitted, with a note: irregular valuation dates
     make annualised volatility meaningless.
   - **positions:** account, ISIN, name (from master data if given), quantity, price and its
     date, currency, value in base currency, weight, cost basis, unrealised P&L;
   - **cash** per account and currency, in both local and base currency;
   - **P&L breakdown:** realised, unrealised, income, costs, cash FX effect, residual (shown,
     and highlighted if not zero);
   - **income and costs** listed by date;
   - **figures:** value over time with flow markers, cumulative TWR, drawdown;
   - **data and assumptions:**
     - provenance of every input (source, dataset, retrieval date, SHA-256 prefix, terms);
     - flow timing, cost basis method (weighted average including charges), FX source and
       staleness limits;
     - carried-forward prices and rates (listed with the requested date and the date used);
     - ledger notes from the broker import;
   - **footer:** "Analytics, not investment advice" (in the chosen language), the qrlab
     version, the reminder to keep reports with real data private.
6. **Warnings are visible**, in a box at the top:
   - stale or carried-forward data;
   - a non-zero P&L residual;
   - several XIRR roots;
   - missing master data.

   Nothing is hidden in a log.

## Hand-calculated and structural tests

| Case | Expected |
|---|---|
| `format_number(1234.5, 2, style=IT)` | `1.234,50` |
| `format_number(1234.5, 2, style=EN)` | `1,234.50` |
| `format_percent(0.0316558, 2, IT)` / `EN` | `3,17 %` / `3.17%` |
| `format_money(Money("-1234.5", EUR), IT)` | `-1.234,50 EUR` |
| Negative zero, NaN, inf | `0,00`; NaN and inf raise (a report never prints "nan") |
| Instrument name `<script>alert(1)</script>` | Appears escaped (`&lt;script&gt;…`), never as a tag |
| Toy portfolio report (synthetic) | Contains the hand values: end value 15.480,00 EUR, P&L 480,00, realised 185,00, unrealised 195,00, income 100,00, TWR 3,17 %, MWR 15,73 %, residual 0,00 |
| Annualisation rule | 88-day toy period: no annualised TWR shown; a 2-year synthetic case shows $(1+TWR)^{365/730}-1$ |
| Determinism | Same inputs → identical bytes for the HTML and every PNG |
| Self-containment | No `<script`, no `src="http`, no `href="http` in the HTML |
| Stale price used | The warning box lists the instrument, the requested date and the date used |
| Structure | Parsed with the standard-library `html.parser`: required sections present in order; one `<img>` per figure with a `data:image/png;base64,` source |

## Edge cases

Empty portfolio (only cash), a portfolio with no flows after the start, a single valuation
date (no returns: TWR section says "not enough dates"), all positions closed, non-EUR base
currency, missing master data for an ISIN (the name shows as the ISIN, with a warning).

## Risks

| Risk | Mitigation |
|---|---|
| Report numbers diverging from the library | The report only formats results of tested functions; the toy report is checked against the hand values |
| Misleading performance presentation | TWR and MWR are separate and defined; no annualisation below one year; volatility only with a declared frequency |
| Private data leaking | No external resources; output path explicit; git-ignored folders; reminder in the footer |
| HTML injection from file content | Every value is escaped; test with a malicious name |
| Non-reproducible output | Explicit `generated_at`; PNG metadata stripped; byte-identical test |

## New dependencies

None (Matplotlib is a runtime dependency; HTML uses the standard library).
