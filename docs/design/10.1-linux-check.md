# Design note 10.1 — the Linux check, locally

Status: **approved 2026-11-16.** First phase of Level 10 (`docs/design/levels-10-13-plan.md`).

## Why

- **The gap.** CI last ran on `main` at `8250b47` (2026-11-13), green on Linux and Windows.
  The 92 commits since then (8.2–8.8, Level 9) ran only on Windows, because the private
  repository's Actions minutes ran out.
- **The rule.** The project rule is to fix what CI finds before publishing, and CI is the
  only place Linux is tested.
- **The fix.** This phase runs exactly what CI runs, on Linux, on this PC. That way
  publication (10.3) does not depend on the minutes coming back.
- **A correction to the level plan:** it said 115 commits and none on Linux. 115 is the count
  since `v0.4.0`, but the first 23 of them did pass CI.

## What runs

The two jobs of `.github/workflows/ci.yml`, step for step:

| Job | Python | Steps |
|---|---|---|
| `checks` | 3.11 and 3.13 | Qt system libraries; `uv sync --locked`; `ruff check`; `ruff format --check`; `mypy`; `pytest --cov` |
| `docs` | 3.13 | `uv sync --locked --group docs`; Sphinx HTML with warnings as errors; Sphinx **doctest** |

The doctest build is not part of the local Windows gate today. It is added to the Windows run
too, so both systems are compared on the same steps.

## Where it runs

- **A WSL 2 Ubuntu distribution,** the release `ubuntu-latest` uses on GitHub (24.04 when
  this note was written; checked again before the run).
- **A fresh clone in the Linux file system** (`git clone` from the Windows checkout into
  `~/qrlab`), not the Windows folder under `/mnt/c`. A clone gets the line endings from
  `.gitattributes` and only committed files, as CI does. It never sees `data/`, the
  untracked `AGENTS.md` or the Windows virtual environment.
- **uv inside Linux,** pinned to the version the project uses on Windows.

## Owner steps (I do not run them)

The two installs need the owner: one needs administrator rights, the other the Linux password
for `sudo`.

1. In a PowerShell window run as administrator:

   ```
   wsl --install -d Ubuntu-24.04
   ```

   Then create the Linux user it asks for.

2. In the Ubuntu window, install the same Qt libraries as CI, plus git:

   ```
   sudo apt-get update && sudo apt-get install -y git libegl1 libgl1 libxkbcommon0 libfontconfig1 libdbus-1-3
   ```

After that I do the rest from here through `wsl`:

- installing uv in the Linux user's home, from Astral's official installer, which is what
  `setup-uv` uses in CI;
- the clone;
- the runs.

## What it delivers

- **`scripts/ci_local.sh`:** runs the CI steps above in order, for a clone path given as an
  argument, and stops at the first failure. Nothing machine-specific is written in it.
- **A test that keeps the script and `ci.yml` together.** It reads every `run:` command of
  the two jobs and checks that the script runs the same commands, so a step added to CI
  cannot be forgotten here. It is a unit test, so it also runs on Windows.
- **`docs/project/` gains "Running the CI checks on Linux locally":** the owner steps above
  and the command.
- **The results,** in this note's results section, with real numbers per job and Python
  version, failures included.
- **Fixes:** every failure gets its own commit, with a regression test that also runs on
  Windows when the cause allows it. A fix too large for this phase stops the phase, and I
  report it instead of patching around it.

## What could differ on Linux

Checked when a failure points at it; none is assumed broken in advance.

- **Case-sensitive file names:** a test or mapping that names `Foo.csv` for `foo.csv`.
- **Encodings:** the default is UTF-8 on Linux and cp1252 on Windows, so a missing
  `encoding=` hides a bug on one system or the other.
- **Line endings** in files the code writes (CSV `newline=""`) and in the expected text of
  tests.
- **Qt off-screen:** the app tests set `QT_QPA_PLATFORM=offscreen`. They need the system
  libraries above.
- **Hashes of outputs:** several tests hash files. A PNG drawn by Matplotlib can differ
  between systems (fonts, FreeType), so a hash of a figure would be a bug in the test.
- **Time zone and locale:** WSL takes the Windows time zone, while CI is in UTC. The run sets
  `TZ=UTC` and `LANG=C.UTF-8`, as on a GitHub runner.
- **Floating point:** NumPy's OpenBLAS may sum in another order, so a test that compares
  floats with `==` instead of a tolerance would fail.

## What it does not cover

- **The Windows app build** (`app-build.yml`): Windows-only, and run before release in 10.3.
- **CI itself:** this is a faithful copy, not GitHub's runner. The first push of `main` (in
  10.3) still runs real CI on both systems, and its result is reported as it is.

## Effort

3–6 h, plus the fixes, whose number is unknown until the first run.

## Results (2026-11-16)

Commit `553b613` (`main` plus this phase's script), fresh clones. The 92 commits since the last
green CI pass on Linux: **no failure, so no fix was needed.**

| Step | Linux 3.11 | Linux 3.13 | Windows 3.11 | Windows 3.13 |
|---|---|---|---|---|
| `ruff check`, `ruff format --check`, `mypy` | clean | clean | clean | clean |
| `pytest --cov` | 2520 passed, 100 % | 2520 passed, 100 % | 2520 passed, 100 % | 2520 passed, 100 % |

The docs job (Python 3.13) passes on both systems: the HTML build succeeds with warnings as
errors, and the doctests give 8 passed, 0 failures. No test was skipped.

- **Environment.** Ubuntu 24.04.5 LTS in WSL 2, with uv 0.12.22 (the Windows version) and
  CPython 3.11.17 and 3.13.16 from uv. The Qt libraries CI installs were already part of the
  WSL image.
- **Deviation: the clone needs `safe.directory` twice.** The checkout under `/mnt/c` belongs
  to the Windows user, so git refuses it. The setting is needed on the clone command and on
  `upload-pack`, because a local clone clears configuration variables (both `-c` and
  `GIT_CONFIG_*`) before starting it. The guide gives the working command; the global git
  configuration is not changed.
- **Not covered:** the app build, which is Windows-only, and real CI, which runs at the first
  push of `main` (10.3).
