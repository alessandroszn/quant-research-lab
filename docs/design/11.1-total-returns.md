# Design note 11.1 — total returns for risk and the checks

Status: **approved 2026-11-16.** First phase of Level 11 (`docs/design/levels-10-13-plan.md`).

## The problem

The `portfolio_report` kind values the portfolio from market prices, and that stays: the
dividends the owner received are already cash in the ledger. But two parts of the report read
**returns**, and both build them from the same price files:

- **the risk section** (8.3): volatility, contributions, VaR and ES, historical stress tests;
- **the diversification checks** (2.4): average correlation, diversification ratio, effective
  number of bets.

A price excludes the income paid out. For a fund that distributes, every ex-date shows up as a
fall of the price by the amount paid, so the price return understates the return and adds a
small spurious move on each ex-date.

### What the kind does today

- `risk` names, in the notice, every position whose price file says `price_type = "price"`,
  with the caveat "their return levels exclude dividends".
- **It names too many.** The price of an **accumulating** fund already holds its reinvested
  income, so it is a total-return series in all but name. The 7.3 design said so, but the
  report still names those funds.
- **It names too few.** A **NAV** series is never named. The NAV of a distributing fund falls
  by each distribution, exactly like its price (7.3 refused `"nav"` in the returns kinds for
  this reason).
- **The checks say nothing** about income at all.

## The change

### 1. Two optional ways to give the income, per fund

Both are keyed by ISIN, and both are for positions that have a price file:

- **(a) A total-return series:** `[inputs.total_returns]` and
  `[inputs.total_returns_mapping]`, one price file and its mapping (phase 1.2). Every column
  must declare `price_type = "total_return"`, and its currency must be that of the position's
  own price file. A typical source is the issuer's NAV total-return history.
- **(b) The distributions:** `[parameters.distributions]`, ISIN = list of
  `{ ex_date, per_unit, currency }`. These are the gross amounts per unit as the fund declares
  them (taxes belong to the tax section). The kind turns them, with the position's own prices,
  into a total-return index:

  $$I_{t_0} = P_{t_0}, \qquad I_t = I_{t-1}\,\frac{P_t + D_t}{P_{t-1}}$$

  - $D_t$ is the sum of the distributions whose ex-date falls in $(t-1, t]$, where $t-1$ is
    the previous price date.
  - So the period's return is the holding-period return $(P_t + D_t)/P_{t-1} - 1$, the usual
    definition (as CRSP's). A distribution between two price dates (weekly prices) enters the
    period that contains it.
  - This works on market prices and on NAVs alike.

**Valuation and the TWR are unchanged:** they keep the market prices and the ledger's cash.

### 2. Which series each position's returns use

A new pure function decides, per held position, which series its returns use and whether that
series includes income. The first rule that applies wins:

| Rule | Series | Income |
|---|---|---|
| a total-return series is given | that series | included |
| distributions are given | the price adjusted as above | included |
| the price file says `total_return` | the price | included |
| an **accumulating** fund (ETF, ETC, fund), `price` or `nav` | the price | included (reinvested in the fund) |
| anything else: a distributing fund, a fund whose policy is unknown, a stock, a bond | the price | **excluded** |

- **The report names every position in the last row** in the notice, as today, but now with
  the reason ("distributing", "policy unknown", "a stock", "a bond").
- **The new wording:** "Risk and the diversification checks use price returns for {names}:
  their return levels exclude the income paid out; volatilities and correlations change
  little."
- **A new table** in the risk section, "Returns used for risk": one row per position, with its
  source (total-return file, price plus distributions, price) and whether income is included.
  It is written as `return_sources.csv`, so a reader can see the rule applied, not only its
  outcome.

### 3. Where the series go

- **Risk** (`compute_risk`): the returns of every position, for volatility, VaR, ES and the
  historical stress tests.
- **The checks:** a new optional field of `CheckContext`, `return_levels` (ISIN → price
  levels, `None` by default = the prices as today). `position_returns` in
  `qrlab.checks.diversification` reads it when it is given.
  - **This is an addition to the frozen public API:** a field with a default. The
    compatibility policy allows it in a minor version (1.1.0), and the API snapshot is
    updated.
- **The new function:** `qrlab.core.returns.distribution_adjusted(prices, distributions)`,
  a pure function on two date-indexed series, also public.

## Edge cases (each raises, naming the ISIN and the date or key)

- **An ISIN not held,** or with no price file, in either input.
- **The same ISIN in both** (a) and (b).
- **(a): a wrong column.** A column whose `price_type` is not `total_return`, or whose currency
  differs from the price file's.
- **(b): a currency** different from the price file's.
- **(b): an amount** that is not positive and finite.
- **(b): two distributions with the same ex-date** for one ISIN. The two amounts are summed
  only if the owner writes the sum.
- **(b): an ex-date outside the price series.** It must be after the first price date and on
  or before the last; otherwise there is no return for it to enter.
- **A gap in a total-return series inside the risk window:** the same error as for a price
  file today. Nothing is filled.
- **Without either input** the kind runs as today, except for the corrected notice (below).

## Outputs that change for configs that do not use the new inputs

These are honest corrections, listed in the CHANGELOG:

- **The notice** no longer names accumulating funds with `price` files, and now names
  distributing funds with `nav` files.
- **The report and the outputs** gain the "Returns used for risk" table and
  `return_sources.csv` when `[parameters.risk]` is set.
- **No number changes:** every return is the same as today unless a new input is given.
- **The byte identity is checked** against `main` on the example configs and on the 8.3 test
  configs. The only differences must be those listed here.

## Tests, hand-calculated first

1. **Distributions on price dates.** Prices 100 (d0), 98 (d1, ex-date d1, $D = 2$), 99 (d2):
   - the index is 100, 100, 101.0204…;
   - so the returns are 0 % and 1.0204 %;
   - the price returns are −2 % and +1.0204 %.
2. **A distribution between price dates.** Prices 100 (d0) and 97.5 (d2), with $D = 2$ ex-date
   d1, which has no price: the return is $(97.5 + 2)/100 - 1 = -0.5\,\%$.
3. **Two distributions in one period,** summed in $D_t$.
4. **Each error above.**
5. **The rule table.** One test per row, plus the notice and its reasons in English and
   Italian.
6. **The risk section** with each input:
   - a total-return file gives the same returns as the equivalent distributions (built from
     the same numbers);
   - the volatility changes by the amount computed by hand on a two-fund case.
7. **The diversification checks** read `return_levels` when it is given and the prices when it
   is not. The second is a regression test of today's behaviour.
8. **Cross-check:** the index from distributions matches pandas'
   `(prices + D).div(prices.shift())` cumulative product on a random seeded series.

## Risks

- **Ex-dates come from the owner.** A wrong ex-date moves income to the wrong period. The
  report lists the source of every position's returns, and the record holds the inputs'
  hashes, so a reader can trace it.
- **An issuer's total-return series** may be in the fund's base currency while the market price
  is in the listing currency. The equal-currency rule refuses that, rather than mixing a
  currency effect into the returns.

## Out of scope (added to `IDEAS.md`)

- **Downloading distributions from issuers.** Each source needs its terms checked (CLAUDE.md).
- **The diversification checks use local-currency returns,** not base-currency ones, unlike
  the risk section. This is a separate question about what those checks should measure.

## Results and deviations (2026-11-16)

- **Built as designed:**
  - `qrlab.core.distribution_adjusted`;
  - the rule and the inputs, in `qrlab.experiments.kinds._return_sources`;
  - `CheckContext.return_levels`, read by the diversification checks;
  - `compute_risk` taking the series;
  - the "Returns used for risk" table, in English and Italian, and `return_sources.csv`.
- **The index is computed as $I_t = P_t \prod_{s \le t} (1 + D_s/P_s)$.** This is the same
  recursion, written so that with no distribution it returns exactly the prices, not prices
  rounded through a cumulative product.
- **Deviation: ETCs.** The rule table put ETCs with the funds that need an accumulating
  policy, but an ETC pays no income, so its price is its total return. It has its own row,
  `NO_INCOME`, and is not named in the notice.
- **Deviation: when the note is given.** The design kept "as today", that is with risk only.
  But the diversification checks read returns too, so the note is now given whenever risk or
  an enabled diversification check reads them. The table stays in the risk section.
- **Deviation: the wording.** "Returns for risk and the diversification checks are computed
  from prices for {names}: they exclude the income paid out, so return levels are understated;
  volatilities and correlations change little." Each name carries its reason.
- **Deviation: a default after the freeze.** `build_portfolio_report` took only required
  inputs, a rule its test enforced, but a new required input would break the frozen API. So
  `return_sources` defaults to `None`. The test now lists the inputs added after the freeze,
  each with its design note.
- **The checks get only the adjusted series** (from a total-return file or distributions),
  not the cleaned prices of the other positions. Today the checks drop a row with a missing
  price; passing the cleaned prices would change their windows.
- **Tests:**
  - 9 core tests, from the hand examples to the cross-check and the refused inputs;
  - 6 tests of the rule;
  - 21 report tests: the 0.645497 % volatility by hand, the file equal to the
    distributions, price and NAV named, the note for the checks alone, the Italian table,
    and every error;
  - 1 check test.
- **The gate:** 2571 tests on Python 3.13 and 3.11, with 100 % coverage; the docs and their
  doctests build.
- **Byte identity against `main`,** on the 8 example configs:
  - **The one difference:** `example_portfolio_report_full` now writes a `NOTICE.txt`. It
    names its distributing fund, which its enabled diversification checks read at price.
  - **Everything else is equal byte for byte,** including that run's `report.html`.
  - **The test configs of 8.3 change as listed above:** two accumulating funds are no longer
    named, and the risk section gains the table.
