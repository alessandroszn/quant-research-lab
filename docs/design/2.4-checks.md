# Design note — Phase 2.4 `qrlab.checks`: portfolio health-check engine

Status: **approved 2026-11-10; implemented.** Deviations, if any, are listed at the end.

## Goal

A configurable engine of health checks on a portfolio. Each check returns findings, never
fixes anything. A finding says:

- what was measured;
- the number observed;
- the threshold crossed;
- the severity;
- a plain-language explanation.

The thresholds are **the user's choices**, stated in a config file. The example config is
marked "example values, not recommendations".

## What can be checked now, and what waits for look-through

Some roadmap checks need data that only phase 2.5 (look-through of ETF holdings, tracking
difference) produces. To avoid half-implemented checks, the plan splits them.

**2.4 — 27 checks, on data that exists today:**

| Category | Checks |
|---|---|
| Concentration | largest position weight; top-5 weight; Herfindahl index (and effective number of positions); single fund-currency exposure |
| Diversification | average pairwise correlation of position returns; diversification ratio |
| Risk | volatility vs. target; maximum drawdown vs. tolerance; historical ES 95 %; beta vs. a benchmark (if one is given); negative skewness (tail risk) |
| Costs | weighted TER; trading-cost drag; estimated total cost of ownership (TER + trading drag) |
| ETF quality | synthetic replication share; domicile outside the preferred list; distribution policy vs. preference; fund size below a minimum; fund younger than a minimum age |
| Currency | unhedged foreign-currency exposure (by fund currency and hedging) |
| Drift | largest deviation from target weights; total drift (rebalancing needed) |
| Data quality | stale prices; stale FX rates; stale master data; missing master-data fields; non-zero P&L residual |

**2.5 — 8 checks, added to the same engine once look-through exists:**
- issuer, country and sector concentration through the holdings;
- holdings overlap between ETFs and redundant funds;
- tracking difference and tracking error;
- TER vs. realised tracking difference;
- stale holdings snapshots.

**3.1:** the effective number of bets needs the covariance and risk-decomposition models of
risk phase 3.1.

That makes 35 checks in total ("about 30" in the roadmap). The roadmap entry for 2.4 is updated
to record the split.

## Framework

```python
class Severity(Enum):
    INFO = "info"
    WARNING = "warning"
    CRITICAL = "critical"


class Category(Enum):
    CONCENTRATION = "concentration"
    DIVERSIFICATION = "diversification"
    RISK = "risk"
    COSTS = "costs"
    ETF_QUALITY = "etf_quality"
    CURRENCY = "currency"
    DRIFT = "drift"
    DATA_QUALITY = "data_quality"


@dataclass(frozen=True)
class Finding:
    check_id: str  # e.g. "concentration.largest_position"
    category: Category
    severity: Severity
    subject: str  # "portfolio" or an ISIN
    observed: float  # the number that triggered the finding
    threshold: float  # the threshold it crossed
    details: Mapping[str, str]  # extra numbers or names, already plain values


@dataclass(frozen=True)
class CheckResult:
    findings: tuple[Finding, ...]
    passed: tuple[str, ...]  # check ids run without findings
    not_applicable: tuple[tuple[str, str], ...]  # (check id, reason), e.g. no benchmark given
```

**Thresholds** come from a TOML file (`configs/checks/example.toml`). Per check:
- `enabled`;
- a `warning` and an optional `critical` level;
- for some checks, parameters such as the return window or `periods_per_year`.

The direction of every check is fixed in the code (for example "above is worse" for the
largest weight), not in the config, so a typo cannot invert a check. Comparisons are strict:
a value exactly equal to the threshold does not trigger, and a test says so for every check.

**Inputs** come in one `CheckContext`:
- as-of date and base currency;
- the ledger history and valuation;
- master data;
- the price series per position (for correlations);
- the TWR series;
- optional: a benchmark return series, target weights, preferences (domiciles, distribution
  policy).

A missing optional input makes the dependent checks *not applicable*, with the reason. It never
makes them pass.

**Plain-language explanations** live in `reporting` (Italian and English labels keyed by check
id), because `checks` (layer 5) cannot import `reporting` (layer 6). The engine returns
structured findings; the portfolio report gains a "Health checks" section that renders them.

**Layering:** `ALLOWED["checks"] = {"core", "data", "instruments", "stats", "metrics",
"portfolio"}`. `reporting` may also import `checks`.

## Definitions and conventions

- **Weights** are base-currency values over the **total portfolio value including cash**. Cash
  has a TER of 0 and its own currency. Stated in the report.
- **Herfindahl index** $= \sum_i w_i^2$ over positions; effective number of positions
  $= 1/\text{HHI}$.
- **Weighted TER** $= \sum_i w_i\,\text{TER}_i$. Unknown TERs are reported as missing data and
  excluded, with the share of weight excluded shown. They are never counted as zero.
- **Trading-cost drag:**
  - trade charges (buy and sell fees and taxes, in base currency) over the period, divided by
    the average portfolio value, annualised by $365/\text{days}$;
  - the trade charges are recorded by the ledger, which gains a `trade_charges` list (a small
    addition to 2.1).
- **Total cost of ownership** $=$ weighted TER + trading-cost drag (annual rates).
- **Diversification ratio** $= \sum_i w_i \sigma_i / \sigma_p$ over risky positions, with
  sample covariance on a stated window of position returns.
- **Average pairwise correlation** is computed on the same window.
- **Return frequency and window** are explicit config values. With fewer observations than
  the window the check is not applicable, never estimated on less.
- **Fund size and age:**
  - fund size needs a new optional master-data field, `fund_size: Money | None` (TOML key
    required; `"unknown"` allowed);
  - age uses the existing `inception` date.
- **Unhedged foreign exposure:** the weight of positions whose fund currency differs from the
  base currency and that are not hedged to it, plus foreign cash. Look-through currency
  exposure refines this in 2.5.

## Hand-calculated tests (one triggering and one passing portfolio per check)

| Case | Expected |
|---|---|
| Weights 0.5, 0.3, 0.2 | largest 0.5; top-5 1.0; HHI 0.38; effective positions 1/0.38 = 2.6316 |
| Largest-position warning at 0.5 with weight exactly 0.5 | no finding (strict comparison) |
| TER 0.20 % and 0.15 % with weights 0.54 and 0.36, cash 0.10 | weighted TER 0.162 % |
| Two assets, σ 20 % and 10 %, ρ 0.5, equal weights | σp = √0.0175 = 13.2288 %; diversification ratio 0.15 / 0.132288 = 1.13389 |
| Trade charges 20 EUR over 88 days, average value 13,000 | drag 20 / 13,000 × 365/88 = 0.638 % a year |
| Weights 0.6 / 0.4, target 0.5 / 0.5 | largest drift 0.10; total drift ½ Σ \|w − t\| = 0.10 |
| Toy portfolio (EUR fund, EUR base) | no unhedged foreign exposure; a USD fund at 30 % gives 0.30 |
| Benchmark not given | `risk.beta` is not applicable with reason "no benchmark" |

## Edge cases

- **Portfolio composition:** a portfolio of only cash; a single position; positions whose
  price series is shorter than the window.
- **Data:** all TERs unknown; a hedged share class; target weights that do not sum to 1 (they
  raise, never rescaled).
- **Config:**
  - a disabled check;
  - an unknown check id (raises);
  - a missing threshold (raises);
  - a critical level less severe than the warning level (raises).

## Risks

| Risk | Mitigation |
|---|---|
| Thresholds read as advice | Thresholds are user config; the example is labelled "not recommendations"; findings state numbers, not instructions |
| False comfort from checks that silently pass | Missing inputs make checks not applicable, with the reason |
| Unknown data treated as zero (e.g. TER) | Unknown values are excluded and reported as data quality findings |
| Inverted checks through config typos | Direction is fixed in code; config validated strictly |
| Checks diverging from metric definitions | Checks call the tested functions of `metrics`, `stats` and `portfolio` |
