# Design note — Phase 6.3d: the working paper

Status: **approved 2026-11-13**, with the proposals P1-P3 as written: the proposed title, no
e-mail in the PDF and a separate DOI. Deviations, if any, are listed at the end. This
detailed note covers 6.3d of the approved note 6.3 (`6.3-release-v1.md`), which it does not
change.

## Goal

One working paper on the four studies, written for researchers and careful practitioners. It
reports what was pre-specified, what was found (null results included) and what it rests on. It
is archived on Zenodo with its own DOI (D5 of note 6.3) and is part of the documentation site.

The paper adds no new analysis. It uses the nine study runs already recorded under
`results/studies/`, and their results and configurations tried are the ones in the reports.

## Every number comes from the records

This is the rigour requirement of 6.3d: **no number is typed by hand.**

1. `scripts/paper_values.py` reads the nine `record.json` files and their tables, and writes:
   - `docs/paper/_generated/values.json`, with every number the text uses, by name (for
     example `s2_max_sharpe_d1_low`) and already formatted with its stated decimals;
   - `docs/paper/_generated/*.md`, with every table of the paper.
2. The text uses MyST **substitutions**: `{{ s3_decay_post_publication }}`, never `-58 %`
   written out. `conf.py` loads `values.json` into the substitutions.
3. The generated files are committed. The raw data are not public, so the docs must build in CI
   without them.
4. `scripts/paper_values.py --check` regenerates the files from the local records and fails if
   anything differs. It runs locally before each release of the paper.
5. In the docs build, any undefined substitution is an error (`-W`). A test checks that every
   value in `values.json` is used at least once, so no stale value survives.

The paper also states the provenance of each run: the commit, the data vintages and their
SHA-256, and the configurations tried. Like everything else, these come from the records.

## Structure (target 9,000–11,000 words, plus tables)

1. **Abstract** (≤ 200 words) and keywords; JEL G11, G12, G14, C12, C58.
2. **Introduction.**
   - The four questions.
   - The common thread: in-sample evidence versus what survives real-time implementation,
     costs, taxes, multiple testing and publication.
   - The contributions: replications on updated data, pre-specified designs, and
     multiple-testing-aware inference.
3. **Methods common to the four studies.**
   - Data and provenance.
   - Pre-registration through design notes.
   - The experiment runner and the trial ledger.
   - Inference: HAC errors, the Jobson-Korkie-Memmel test, the stationary bootstrap, Holm,
     BH and BY corrections, and the deflated Sharpe ratio.
   - Costs, taxes and timing conventions.
4. **Study 1 — volatility-managed factors.**
5. **Study 2 — 1/N against optimised portfolios.**
6. **Study 3 — the factor zoo.**
7. **Study 4 — rebalancing for a EUR ETF investor.**

   Sections 4–7 share one layout: question and hypotheses, data and specification, in-sample
   results, out-of-sample or real-time results, statistical and economic significance, and
   robustness. Each condenses its report, which stays the full account.
8. **Discussion.** What the four have in common:
   - estimation error;
   - frictions;
   - publication and data revisions;
   - why null results are informative here.
9. **Limitations.** Taken from the four reports and the methodology pages:
   - survivorship and data revisions;
   - a single tax regime;
   - gross returns in study 3;
   - and so on.
10. **Conclusion.**
11. **References.**
12. **Appendices.**
    - A: reproducibility (software version, commits, configs, data vintages with SHA-256,
      licences, and how to rerun).
    - B: configurations tried and deviations from the design notes.
    - C: data terms.

## Format and build

- **Source:** `docs/paper/`, in MyST Markdown, built by Sphinx like the rest of the site. The
  HTML version lives on the site.
- **PDF:** the Sphinx LaTeX builder with the `howto` (article) class, built **locally** with the
  MiKTeX already installed on this machine (`pdflatex`).
  - It is not built in CI: installing TeX in CI would cost minutes and add no check that the
    HTML build lacks.
  - On its first run MiKTeX may want to download missing LaTeX packages. I will ask before
    letting it download anything.
- **Licence:** CC BY 4.0, as for the rest of the documentation.
- The PDF is not committed. It is attached to the Zenodo record and to the GitHub Release,
  with its SHA-256.

## Tests

- **`paper_values.py` on synthetic records:**
  - values and tables are generated with the stated rounding;
  - a missing record or table raises;
  - `--check` passes on identical output and fails on a changed number.
- **Every substitution is used** in the paper, and every one the paper uses is defined. The
  second half is also enforced by the docs build with `-W`.
- **Local cross-check:** `paper_values.py --check` against the real records before the PDF is
  built.
- **Spot check by hand:** I recompute three numbers per study from the record tables and
  compare them with the paper.

## Risks

- **Length and scope.** The paper condenses about 7,800 words of reports; there is a risk of
  rewriting the studies. It reports what is recorded and adds no analysis. Anything new goes to
  `docs/IDEAS.md`.
- **LaTeX on Windows.** MiKTeX may need packages (see "Format and build"), and long tables can
  break across pages. If the LaTeX route proves fragile I will come back to you before changing
  the tool.
- **Consistency with the reports.** A number that differs between the paper and a report would
  be a defect. Both come from the same records, and the spot checks compare them.

## Deviations

- **The study sections were drafted in parallel.** Four helper agents each condensed one report
  into its section and its values file. Each checked its values against the records and
  reported the numbers it left out. Then:
  - I spot-checked at least three values per study directly against the tables;
  - I wrote the abstract, introduction, methods, discussion, limitations, conclusion,
    references and appendix.
- **The reports had last-digit errors.** Generating the paper from the records found 13 figures
  in the four reports that differed in the last digit, mostly from rounding twice, and one
  overstated claim ("lowest Sharpe ratio", study 2). The reports are corrected in the same
  change and listed in the CHANGELOG.
- **Very small p-values.** They are printed as "< 0.0001", computed from the value by a `below`
  option of the generator, instead of in scientific notation, which pdflatex cannot typeset
  from Unicode superscripts.
- **The commit caveat.** Every study record shows uncommitted changes at run time. Appendix A
  says so, and a clean re-run is recorded in `docs/IDEAS.md`.
- **MiKTeX downloads without asking.** While checking which LaTeX packages were missing, my
  `kpsewhich` calls triggered MiKTeX's automatic installer, which on this machine installs
  without asking. 18 packages were downloaded from MiKTeX's repository before I noticed; I
  reported this to the owner. Later builds use `pdflatex --disable-installer`, so nothing is
  installed. The PDF still needs at least one more package (`letltxmacro`), whose installation
  is the owner's decision.
