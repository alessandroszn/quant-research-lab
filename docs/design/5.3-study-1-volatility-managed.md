# Design note — Phase 5.3, study 1: volatility-managed portfolios

Status: **approved 2026-11-12.** Deviations, if any, are listed at the end.

## Question

Moreira and Muir (2017, *JF*) report that scaling a factor's exposure by the inverse of its
recent realised variance gives large, significant alphas against the unmanaged factor.
Cederburg, O'Doherty, Wang and Yan (2020, *JFE*) report that these in-sample spanning alphas
mostly do **not** turn into higher Sharpe ratios for a real-time investor, because the scaling
constant and the combination weights are not known in advance.

**Hypotheses, stated before running:**

- **H1 (replication).** In sample, the volatility-managed version of each factor has a
  positive alpha against the unmanaged factor.
- **H2 (implementability).** Out of sample and after costs, the volatility-managed version does
  not have a significantly higher Sharpe ratio than the unmanaged factor, after correcting for
  the six factors tested.

An honest null result is a valid result and is reported as such.

## Data

- **Ken French factor files, daily and monthly** (US, in USD):
  - market excess return (Mkt-RF), SMB and HML (FF3);
  - RMW and CMA (FF5);
  - momentum (Mom).
- **Terms.** These were already checked in phase 1.2: free for research, and the data are
  never redistributed.
- **Storage and download.**
  - The files are stored unchanged in the raw store, with provenance and SHA-256.
  - The study reads them from local files; downloading is a separate, explicit step that I will
    ask you to approve before it runs. That step uses the existing fetcher and downloads six zip
    files of a few MB from mba.tuck.dartmouth.edu.
- **Sample.** The full history of each file, and also the sample closest to the paper's
  (Mkt from 1926 to 2015) for comparison.

## Method

- **Monthly realised variance.**
  - $RV_t = \sum_{d \in t} f_d^2$, the sum of squared daily returns of the factor in month $t$.
  - **Deviation from the paper**, stated in the report: Moreira–Muir demean daily returns
    within the month; I sum raw squares, because the daily mean is negligible.
  - A sensitivity run uses demeaned returns.
- **Managed factor:** $f^\sigma_t = \dfrac{c}{RV_{t-1}} f_t$. The weight uses only the
  **previous** month's variance (lag 1, no look-ahead).
- **In sample (H1), following the paper:**
  - $c$ is chosen on the full sample so that $f^\sigma$ has the same volatility as $f$.
  - The spanning regression is $f^\sigma_t = \alpha + \beta f_t + \varepsilon_t$ (`stats.ols`,
    Newey–West, lags explicit: 6).
  - Reported: annualised $\alpha$ and its $t$-statistic, the appraisal ratio
    $\alpha/\sigma_\varepsilon\sqrt{12}$, $R^2$ and $N$.
- **Out of sample (H2), following Cederburg et al.:**
  - $c_t$ is estimated in real time from data up to $t-1$, with an expanding window and an
    explicit 120-month burn-in.
  - The weight is capped at an explicit maximum leverage (5×), with a sensitivity run at 2× and
    without a cap.
  - The managed and unmanaged factors are compared on the same out-of-sample months:
    - Sharpe ratios;
    - the Ledoit–Wolf HAC test of the difference (5.1);
    - a stationary-bootstrap interval.
- **Costs.** Managing the exposure creates turnover $|w_t - w_{t-1}|$. Net returns subtract
  turnover times a cost per unit traded, with 0, 10 and 25 basis points as explicit scenarios.
  The unmanaged factor has no turnover cost in this comparison; its own rebalancing costs are
  the same in both and so cancel out.
- **Multiple testing.** Six factors are tested:
  - Holm and Benjamini–Hochberg on the six alpha p-values (H1) and the six Sharpe-difference
    p-values (H2);
  - the DSR of the best managed factor, with $N$ equal to the configurations tried, as recorded
    by the runner's trial ledger.

## Implementation

- **Package `qrlab.studies`**, documented in `ARCHITECTURE.md`:
  - it sits between the library and `experiments`, and may import every library package
    including `reporting`;
  - `experiments` may import `studies`.
- **`studies.volatility_managed`** holds pure functions: realised variance, managed weights
  with an explicit lag, the full-sample and real-time constants, turnover and costs, and the
  in-sample and out-of-sample tables. They are tested on synthetic data.
- **Experiment kind `study_volatility_managed`:**
  - inputs: the six local Ken French files;
  - parameters: factors, burn-in, leverage cap, cost scenarios, HAC lags, the demeaning flag
    and the sample window;
  - outputs: tables tagged in or out of sample, an HTML report, and the record.
- **Written report** `docs/studies/01-volatility-managed.md`: question, data with hashes,
  method, in-sample and out-of-sample results side by side, multiple-testing results,
  limitations, and the conclusion stated against H1 and H2. It is written **after** the run,
  with the actual numbers, whatever they show.

## Tests (synthetic data, no network)

| Case | Expected |
|---|---|
| Daily returns ±1 % for 20 days in month 1 and ±2 % for 20 days in month 2 | $RV_1$ = 0.0020, $RV_2$ = 0.0080; with $c$ = 1 the weights for months 2 and 3 are 500 and 125 |
| Constant daily volatility (seeded, homoskedastic) | weights constant up to sampling noise; in-sample $\alpha$ not significant |
| GARCH-like simulated data where volatility predicts lower risk-adjusted returns | positive in-sample $\alpha$ (direction check) |
| Changing the returns after month $t$ | weights up to $t+1$ and real-time $c$ up to $t$ unchanged (no look-ahead) |
| Full-sample $c$ | $\operatorname{std}(f^\sigma) = \operatorname{std}(f)$ exactly |
| Turnover cost, weights 1.0 → 1.5 → 0.5, 10 bp | costs 0.0005 and 0.0010 |
| Leverage cap 5 | no weight above 5 |
| End to end on synthetic Ken French–format files | the kind runs through the CLI, and tables carry the right tags |

## Risks

- **Data revisions.** Ken French revises history, so numbers will not match the paper exactly.
  The report compares signs and magnitudes and records the file hashes.
- **Look-ahead.** It is avoided by the lag-1 weights and the real-time $c$, and checked by a test.
- **Specification search.** All variants (cap, costs, demeaning) are fixed in this note before
  running. Every run is counted by the trial ledger, and the DSR uses that count.

## Deviations

- **Signal lag** is fixed at one month in the experiment kind (`SIGNAL_LAG`), as the note
  specifies; the library function takes it as an explicit argument.
- **Bootstrap settings, significance level and the sample window** are config parameters
  (`bootstrap`, `significance`, `start`, `end`); the note fixed only their roles.
- **Deflated Sharpe ratio.** The variance of the trial Sharpe ratios is estimated from the
  variants of the current run (factors x caps x costs). The number of trials is that count times
  the configurations recorded in the trial ledger (`experiments.configurations_tried`, added for
  this purpose). Sharpe ratios of earlier configurations are not stored, so their dispersion is
  assumed to be similar.
- **Missing values.** Leading and trailing missing values of each factor inside the window are
  trimmed (RMW and CMA start in 1963); a missing value inside the window stops the run.
- **Raw-store provenance.** When an input file has a `.provenance.json` sidecar from the raw
  store, its hash is checked and its download URL and date go into the report; otherwise the
  provenance is the local file.
- **Turnover cost of the first out-of-sample month** is zero: the initial position is not
  charged, as for the unmanaged factor.
