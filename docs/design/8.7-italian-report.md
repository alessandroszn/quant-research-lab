# Design note — Phase 8.7: a report entirely in Italian

Status: **approved 2026-11-14.** Deviations, if any, are listed at the end. Seventh phase
of Level 8 (`docs/design/level-8-plan.md`).

## The problem

The report's own labels are translated (`qrlab.reporting.labels`), but it also shows text that
the library writes in English. I ran the full example in Italian and listed what is left
(14 November 2026):

| Source | Example in today's Italian report | Where it is written |
|---|---|---|
| Import notes | "File listed newest first; rows reversed as a whole (chronological order)." | `portfolio.broker_import`, `data.user_csv`, `instruments.io`: about 15 sentences |
| Why a check does not apply | "needs holdings of at least two funds", "no benchmark given" | `NotApplicable(...)` in `qrlab.checks`: 28 places |
| Metric errors passed on by the checks | "4 observations leave a tail of 0.2 at confidence 0.95; need >= 1" | `UndefinedMetricError(...)`: 30 places |
| Measurement details | "issuer: US0000000119; unexplained: 0.001744; grouping: security, not issuer (no issuer map)" | the `details` of `Measurement` in the checks |
| Subjects | "portfolio" | the checks |
| Text the report puts together | the tax sources, the reason a Sharpe ratio is missing, the Cornish-Fisher note | `qrlab.tax`, the kind, `_portfolio_risk` |

## Design

### 1. A catalog of library messages (`qrlab.reporting.messages`)

- **An ordered list of templates.** Each pairs a regular expression matching one English
  message with its Italian form, and the captured values are carried over unchanged. For
  example:

  ```text
  r"(\d+) common returns, fewer than the window of (\d+)"
      -> "{0} rendimenti comuni, meno della finestra di {1}"
  ```

- **`translate(text, language) -> str`.** English returns the text unchanged. In Italian, the
  first full match is translated. A message with no match is shown in English, so nothing is
  ever dropped, and the test in point 3 makes sure every known message has a match.
- **Number formatting.** Values captured in a message, such as "0.2" or "0.95", are numbers
  formatted by the library. In Italian they get the Italian decimal comma, through the same
  formatting functions as the rest of the report.
- **Measurement details.** Keys such as `effective_positions` and `excluded_weight` get labels
  in both languages. The few fixed phrases ("security, not issuer (no issuer map)") are in the
  catalog. The subject "portfolio" becomes "portafoglio".

### 2. Where the report uses it

- Import notes and holdings notes.
- The reasons in the "not applicable" table of the health checks.
- Measurement details and subjects.
- The Sharpe reason (8.5) and the Cornish-Fisher note (8.3).
- The tax sources (8.6): `qrlab.tax` gets an Italian list of the same sources next to the
  English one, chosen by the report. Legal citations are Italian anyway; only the comments
  around them change.
- **Unchanged on purpose:**
  - the provenance terms, which are recorded data, quoted as written (the column header says
    "as recorded");
  - names and descriptions you write yourself, such as titles, scenario descriptions and
    instrument names.

### 3. The guard test: no message can be left behind

- **A static scan of the source** (`ast`, no execution) collects every message template the
  library can show in a report:
  - string literals and f-strings passed to `NotApplicable(...)` and `UndefinedMetricError(...)`;
  - those appended to `notes` in the parsers;
  - the keys of `Measurement` details.

  An f-string becomes a pattern, with each `{...}` replaced by a wildcard.
- **The test asserts that each template is matched by a catalog entry,** using a sample of the
  template. A new message added without a translation then fails the test suite, instead of
  surfacing as English in someone's report.
- **End to end:**
  - the full example and the test portfolios are rendered in Italian;
  - the visible text must contain none of a list of English marker words used by library
    messages ("needs", "given", "known", "fewer than", "listed", "ignored", …);
  - titles and provenance are excluded from that check.

## A change to the plan

Level 8 also listed "total-return position returns for the diversification checks". For an
accumulating ETF the price is already a total-return series, but a distributing fund would
need a new kind of input (a total-return file per fund). That moves to IDEAS. The risk
section already says when it uses price-only returns (8.3).

## Tests (hand-calculated first)

- **Each catalog entry, both ways.** For example, "3 common returns, fewer than the window of
  36" becomes "3 rendimenti comuni, meno della finestra di 36", and "4 observations leave a
  tail of 0.2 at confidence 0.95; need >= 1" gets the Italian decimal comma (0,2 and 0,95).
- **English stays byte-identical.** The `portfolio_report` examples in English, and the
  English test reports, are unchanged against `main`.
- **Italian changes only where English text was.** The Italian example report differs from
  `main` only in the translated messages. The diff is reviewed and listed in the deviations.
- **The guard test** (point 3) and the end-to-end Italian check.

## Risks

- **A catalog by pattern can drift from the library.** That is why the static guard test fails
  as soon as a message has no pattern.
- **Over-translation.** Only full-message matches are translated, never fragments, so your own
  text is never touched.
