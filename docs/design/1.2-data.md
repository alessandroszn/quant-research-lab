# Design note — Phase 1.2 `qrlab.data`

Status: **approved 2026-11-10; implemented.** Deviations from the draft are listed at the end.

## Goal

Analytics never depend on where data comes from. Every external file is stored byte-for-byte
as downloaded, with provenance, and parsed by a pure function into a validated, documented
dataset (units, frequency, return kind, currency, availability).

## Data sources and terms of use (checked 2026-11-10)

| Source | Terms found | Decision |
|---|---|---|
| **Kenneth French Data Library** (factors, portfolios) | No licence or terms on the page; only a copyright notice for Fama and French. Universally used in academic research with citation. | **Use** for local research with citation. Raw files are never committed or redistributed; test fixtures are small synthetic files in the same format. |
| **ECB euro reference FX rates** (`eurofxref-hist.zip`) | ECB website disclaimer: free use of information taken from the site if reproduced accurately and the ECB is cited; modifications must be stated. Rates are "for information purposes only". | **Use**, with attribution in reports. |
| **ECB Data Portal** (€STR, euro-area HICP, yields) | Same ECB terms. | **Use** as the source for the euro risk-free rate and inflation. |
| **FRED** (St. Louis Fed) | API key required; the terms **prohibit storing, caching or archiving** FRED content and incorporating it into a database or cache without written consent; some series need copyright pre-approval; no AI/ML training use. | **Not used.** It conflicts with the rule that raw downloads are stored unchanged. For a EUR investor the ECB covers rates and inflation. Recorded in `docs/IDEAS.md`. Change from the roadmap; needs approval. |
| **Free ETF price source** | Not chosen yet. | Deferred, as in the roadmap. User-supplied CSV always works. |
| **Open Source Asset Pricing** (Chen and Zimmermann; checked 2026-11-12, study 3) | Hugging Face dataset `OpenSourceAP/CrossSection` licensed **CC BY 4.0**; the authors ask to cite Chen and Zimmermann (2022). Reports produced with these data cite the source (ECB, Kenneth French Data Library).

## Scope and proposed split (one PR each)

1. **1.2a Store and provenance:** raw store, provenance records, fetcher interface, dataset
   container.
2. **1.2b Ken French:** download and parse factor files (FF3, FF5 2×3, momentum; monthly and
   daily).
3. **1.2c ECB:** reference FX rates; €STR; HICP index.
4. **1.2d User CSV prices:** explicit mapping of the user's own price files.

**Proposed change: broker transaction import moves to phase 2.1.** Its schema (buy, sell,
dividend, fee, tax, FX…) is defined by the accounting model of 2.1, and `data` (layer 1) cannot
depend on `portfolio` (layer 4). Designing the schema twice would be wasted work. 1.2 ships the
generic CSV mapping layer that 2.1 will reuse.

## 1.2a Store and provenance

```python
@dataclass(frozen=True)
class Provenance:
    source: str  # e.g. "ken_french", "ecb_exr"
    dataset: str  # e.g. "F-F_Research_Data_Factors"
    url: str
    retrieved_at: datetime  # timezone-aware UTC
    sha256: str
    size_bytes: int
    terms: str  # short note, e.g. "ECB: free reuse with attribution"


class Fetcher(Protocol):
    def fetch(self, url: str) -> bytes: ...


class UrlFetcher:  # stdlib urllib; explicit timeout; generic User-Agent "qrlab/<version>"
    ...


class RawStore:
    def __init__(self, root: Path) -> None: ...  # root is explicit, e.g. <repo>/data
    def put(self, content: bytes, provenance: Provenance) -> StoredFile: ...
    def latest(self, source: str, dataset: str) -> StoredFile: ...
    def vintages(self, source: str, dataset: str) -> list[StoredFile]: ...
    def read(self, stored: StoredFile) -> bytes: ...  # verifies SHA-256 on every read
```

Rules:
- Layout: `root/raw/<source>/<dataset>/<UTC timestamp>_<sha256[:12]>.<ext>` with a sidecar
  `….provenance.json`.
- **Never overwrite.** A download with the same hash as the latest vintage reuses it; a
  different hash creates a new vintage. Old vintages are kept, because some sources (notably
  Ken French) revise history. Reproducing a past result means reading the vintage it used.
- Stored files are set read-only. `read` recomputes the hash and raises on mismatch.
- Downloading (network) and parsing (pure, bytes → dataset) are separate. Tests use a fake
  `Fetcher`; **no network in tests**.
- No new dependency: `urllib`, `zipfile`, `hashlib`, `json` from the standard library.

```python
@dataclass(frozen=True)
class Dataset:
    data: pd.DataFrame  # validated with qrlab.core.series
    provenance: Provenance
    frequency: Frequency
    unit: Unit  # DECIMAL (0.01 = 1%), PERCENT, INDEX_LEVEL, PRICE, FX_RATE
    return_kind: ReturnKind | None
    currency: Currency | None
    availability: str  # how the data became known, e.g. "ECB publishes ~16:00 CET on the date"
    notes: tuple[str, ...]  # e.g. "Mkt-RF is an excess return"
```

Parsers return returns in **decimal** units; percent sources are converted explicitly and the
conversion is recorded in `notes`.

## 1.2b Ken French

- Download `ftp/<name>_CSV.zip`. Each file has text headers, then sections (monthly, annual)
  separated by blank lines and section titles.
- Parsing is **strict**: the expected header and columns must be found, otherwise
  `ValidationError`. A silent change of format must never produce wrong numbers.
- Monthly dates `YYYYMM` → month end; daily `YYYYMMDD`; annual `YYYY` → year end.
- Missing-value codes `-99.99` and `-999` → NaN. Percent → decimal.
- `RF` is the one-month T-bill return; `Mkt-RF` is an excess return. Both in USD.
- Availability: the library is updated irregularly and revised; the vintage (download date)
  is the only availability information. Documented as a limitation.

Hand-calculated test (synthetic fixture):

| Line | Expected |
|---|---|
| `202601,    1.23,   -0.45,    0.10,    0.33` | 2026-01-31: Mkt-RF 0.0123, SMB −0.0045, HML 0.0010, RF 0.0033 |
| `202602,  -99.99, ...` | 2026-02-28: Mkt-RF NaN |
| Annual section `2026, 10.00, ...` | separate dataset, 2026-12-31: 0.10 |

## 1.2c ECB

- **FX:** `eurofxref-hist.zip`: one CSV with a column per currency, quoted as units of currency
  per 1 EUR, so each value is an `FxRate(EUR, X, rate, date)` in `qrlab.core` terms. `N/A` → NaN;
  no forward fill (a missing rate stays missing; the portfolio layer decides the staleness
  policy). Dates are TARGET2 business days; published around 16:00 CET.
- **€STR** (daily, percent per year, from 2019-10-01) and **euro-area HICP index** (monthly):
  ECB Data Portal SDMX API, CSV format. Series keys are confirmed at implementation and
  pinned in code.
- Per-period risk-free returns from an annual rate need a day-count convention (€STR is
  ACT/360). That conversion belongs to `metrics`/`portfolio`, not to the parser; the parser
  keeps the published annual percentage, converted to decimal.
- HICP: the published value for month *m* becomes available about mid month *m+1*. The
  dataset records an explicit `publication_lag` parameter (required, no default) and an
  `available_from` column, so later phases cannot use it before it was known.

## 1.2d User CSV prices

```python
@dataclass(frozen=True)
class CsvMapping:
    date_column: str
    date_format: str  # e.g. "%d/%m/%Y" — never guessed
    decimal_separator: str  # "." or "," (Italian broker exports use ",")
    thousands_separator: str | None
    columns: Mapping[str, ColumnSpec]  # value column -> instrument, currency, PriceType
```

- `PriceType`: `TOTAL_RETURN` (dividends reinvested), `PRICE` (dividends excluded), `NAV`.
  Required per column; the roadmap requires the total vs price flag.
- Every ambiguity raises: unparseable dates, duplicated dates, mixed separators, unknown
  currency.
- Mappings live in `configs/`. Files live in the git-ignored `data/`.

## Edge cases (tested for every parser)

Empty file, header only, unexpected header, extra or missing columns, missing-value codes,
duplicated or unsorted dates, a hash mismatch on read, the same content downloaded twice (one
vintage), a changed content (two vintages), a non-UTC timestamp (rejected).

## Risks

| Risk | Mitigation |
|---|---|
| Silent format changes upstream | Strict parsers that fail loudly; fixtures for the expected format |
| Revisions of historical data (Ken French) | Vintages kept; results reference the hash used |
| Percent vs decimal confusion | Explicit `Unit`; parsers output decimals; tests on hand values |
| Look-ahead through publication lags (HICP) | `available_from` column; required `publication_lag` |
| Terms of use | Table above; FRED excluded; raw data never committed |
| Network flakiness | One explicit attempt with a timeout; errors surface, nothing partial is stored |
| Personal data | User CSVs only under `data/`; fixtures are synthetic |

## Layering

`data` imports only `core` (already allowed). Sub-modules stay inside `qrlab/data`.

## New dependencies

None.

## Effort

20–30 h, as in the roadmap, over the four PRs above.

## Deviations found during implementation

- **HICP series key.** The ECB discontinued the `ICP` dataset on 4 February 2026 (Eurostat
  methodology change). The parser is pinned to the replacement `HICP.M.U2.N.000000.4D0.INX`
  (base 2025 = 100, from 1990). Latest months carry status `E` (flash estimate).
- **`Dataset` gained `available_from` and `status`** (optional series aligned with the data)
  instead of an `available_from` column, because data columns must stay numeric. Availability
  can never precede the reference date. €STR is available on the next TARGET2 business day; ECB
  FX on the same day; HICP after the caller's `publication_lag_days`.
- **`Unit`** is `RETURN`, `RATE_PER_YEAR`, `INDEX_LEVEL`, `PRICE`, `FX_RATE`: percentages are
  always converted, so no `PERCENT` unit is needed.
- **User files:** provenance URL `file:<name>` (name only, never a path); `import_local_file`
  copies a local file into the raw store.
- **CSV mapping:** one currency per mapping (not per column), so a dataset never mixes
  currencies; `PriceData` returns the price type of each instrument; newest-first files are
  reversed and the reversal is noted; the declared frequency is checked against the dates.
- **Ken French portfolio files** (e.g. 25 size/value portfolios) are not parsed yet: their
  files contain several tables (value- and equal-weighted, counts, sizes) and are added when a
  study needs them.
- **Verification against live sources** was run outside the test suite on 2026-11-10 (files
  downloaded to a temporary folder and deleted): all six Ken French datasets, the ECB FX history
  (7,132 days, 41 currencies), €STR (1,821 days) and HICP (442 months) parse without errors.
